### 独立访问

生成包内的 `server/console.py` 同时提供登录页和管理 API。单独运行时，矩阵发业务服务校验企业账号，管理员在同一个地址查询业务和提交任务。浏览器无需依赖天枢前端或登录会话。将本目录的 [矩阵发独立服务配置](standalone.json) 复制到私有运行目录，按环境设置两个地址，然后在解压的生成工程下执行：

```sh
python3 -m unittest discover -s server
python3 server/console.py --config /绝对路径/console.json
```

配置示例使用本机 9530 提供管理页面、18091 连接矩阵发业务服务。企业管理员可在名下设备中选择任务目标，员工只获得配置中的读取权限。独立服务的请求回执保存在配置同目录。

## 系统分工

| 入口 | 首期职责 | 后续扩展 |
| --- | --- | --- |
| 天枢 PC 和手机工作台 | 登录、应用开通、分配查看权限，按清单展示发布结果 | 增加设备、素材、任务页面和各自操作权限 |
| 矩阵发业务服务（`juzhenfa/juzhenfa`） | 验证平台请求，将用户绑定到本地账号，从自己的库读取结果 | 沿用已有的配额、任务调度、设备连接和结果回传 |
| 矩阵发企业控制台（`matrix-push-frontend`） | 联调时和现有业务记录对账 | 上传素材、编排任务、实时监控可沿用现有页面。要从天枢免登打开这些页面，还需接通浏览器单点登录 |
| Android 执行端（`JuzhenFaApp`） | 保持设备原有的绑定、心跳和回执 | 设备继续使用自己的身份。员工在天枢手机端查看任务，执行手机的在线状态由矩阵发提供 |
| 矩阵发运营后台（`matrix-admin-console` 和 `juzhenfa-manager`） | 供矩阵发运营人员管理服务 | 企业租户开通应用时仅获得企业业务权限 |

## 单页只读方案

员工登录天枢后，打开矩阵发。PC 和手机都调用行业应用的 `query` 动作。天枢检查当前租户是否开通、当前用户是否有 `biz_matrix_push:query` 权限，再通过行业网关向矩阵发发送 `POST /apps/matrix_push/actions/query`。[平台接入协议](../../docs/DEVELOPING_INDUSTRY_APPS.md)

矩阵发需要实现这一条内部接口并配置该应用的网关路由。后端用该应用的密钥验证签名、时间、应用编码及动作，从已签名请求取出租户和用户。部署时保留网关对现有应用的路由，仅为 `matrix_push` 新增目标。矩阵发当前开发配置占用的默认端口和天枢重合，联调时给矩阵发分配独立端口，并对齐其前端的 HTTP 和 WebSocket 代理。

身份绑定由管理员分别确认天枢租户对应哪家矩阵发企业、天枢成员对应哪个业务账号。按集成来源、租户 ID 和用户 ID 查绑定，校验目标账号仍属于该企业且租户可用。绑定缺失、停用或归属不一致时拒绝读取。现有发布结果列表按企业查询，开放给员工前需要加上账号的数据范围。首期建议普通员工仅看自己的任务，获准的企业管理员可看本企业任务。两边企业同名、用户同名或数字 ID 相同，均不足以自动建立绑定。

天枢对上游 HTTP 403 显示无权访问，对连接或超时错误显示服务不可用。

矩阵发现有 `/api/publish-results` 使用自身登录态，返回分页对象，记录中含设备、日志等附加信息。天枢的原生列表需要数组。适配接口应在矩阵发业务层按租户和成员范围查询，按创建时间、任务 ID 倒序取最近 20 条，再返回下表五列。普通筛选使用 MyBatis-Plus，需要跨表关联的查询放在 Mapper XML。

| 天枢清单字段 | 矩阵发来源与显示约定 |
| --- | --- |
| `task_no` | `taskNo`，与企业控制台对账的任务编号 |
| `title` | `titleFinal`，允许为空 |
| `status` | 任务状态，按已有业务含义显示待执行、执行中、成功、失败、已取消 |
| `progress` | `progress`，保留真实进度，缺少进度时留空 |
| `finished_at` | `finishedAt`，保留时分秒，未完成时留空 |

## 扩到整套业务

矩阵发设备登记的 `DeviceController.create` 在缺少租户时写入常量 `1`，`DeviceServiceImpl.createDevice` 又沿用非空的传入值。开放设备登记前，应由业务服务从已验证的账号确定所属企业，校验配额和写入使用同一个租户，并单独核对历史设备归属。

行业清单现已支持一个应用多个页面。每页拥有独立的列表、操作和查询权限，PC 和手机共用。优先沿用现有的矩阵发调度与业务数据。任务创建应返回任务编号，后续按编号读取执行结果，重复提交同一请求只创建一个任务。支付沿用项目暂缓范围。

## 联调验收

1. 将两套系统中 ID 不同的测试企业和业务账号明确绑定，准备两家企业、同一家企业两名员工的任务。只给试点企业开通，给一名员工授予查看权限。PC 和手机应显示同一任务编号、状态、进度和完成时间，并能与矩阵发控制台逐项对上。
2. 使用另一家企业、同企业另一名员工、未绑定账号分别验收。各账号只能读取其获准的记录。停用试点租户的应用后用已登录会话刷新，同时检查其他应用仍可打开。
3. 暂停隔离联调环境里的矩阵发服务。天枢应显示服务不可用，恢复后可读回原记录；成功、空列表和服务不可用应有不同表现。
4. 扩展写入时，使用测试设备验证从创建任务到设备领取、状态回传的整条链路，核对重复提交、配额及撤权。单独验收大文件上传和长连接。首期只读验收无需向外部平台发布内容。
