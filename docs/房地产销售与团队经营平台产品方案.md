# 天枢房地产销售与团队经营平台

产品设计稿 · 2026 年 11 月 27 日  
2026 年 11 月 28 日确认交付范围。任务分派、里程碑和验收以[开发实施方案](房地产销售平台开发实施方案.md)为准。已取消“获客与渠道运营”模块，客户来源、企业派单、内部流转、项目报备和结算仍保留。
首个业务场景为新房销售，覆盖开发商自销、代理案场和渠道分销。小团队可以只开客户、带看和成交模块。集团可以按城市、门店、项目和结算主体运营。以下业务规则和规模指标均为拟议设计。

## 一组家庭客户怎样走到成交

假设小周通过老业主介绍认识陈女士。她想找三房，先留了自己的电话。小周可以立即建个人档案，约好周五联系。后来才得知，她先生在意通勤，母亲希望能坐电梯直达车库，全家可接受的总价是 280 万。销售给这次购房建一个家庭档案，把三人的关注点分别记下。“母亲”可以只是家庭成员称谓，无须补姓名和手机号。

陈女士的先生又从公司广告留了资。系统保留这次广告线索，经核实把两人的记录关联到同一次购房。保留该条公司资源的来源，门店仍然只统计一个购房机会。夫妻各自同意的联系方式分别保存。

后来陈女士希望改看城南。小周经客户同意把这个机会投到城南团队公海，填写交接摘要。小林认领后能看到客户关心什么、哪些房已经看过、答应何时回电。小周能看到自己的推荐是否被接收、是否形成应计提成。小林邀约夫妻复看，完成认购。财务按这一单生效的规则确认小周的推荐贡献和小林的成交贡献。经理从始至终只看到权限允许的内容。

## 1. 客户、家庭与购房机会

| 业务对象 | 保存什么 | 销售怎么用 |
| --- | --- | --- |
| 个人客户 | 称呼、联系方式或平台线索号、可联系时段、偏好渠道、勿扰要求、最近一次有效联系 | 首次只录已知信息。后续补充，保留更正和来源。一个人可参与自己改善住房、替父母置业等不同机会 |
| 家庭与共同购买人 | 成员、相互关系、是否常住、主要联系人。每人可同时具有出资、居住、选房、共同决策、签约等角色。朋友或伴侣共同买房也可建组 | 区分“此次还要谁看过才定”和“谁愿意接电话”。另购一套可以新建机会，保留原来的家庭关系 |
| 成员兴趣 | 每人对户型、楼层、采光、通勤、车位、电梯、安静程度、装修的偏好。客户主动谈到的生活兴趣，如养宠物、骑行、园艺，可注明与选房的关联 | “母亲需要电梯直达车库”“陈女士想要能放书桌的第三间房”。一条偏好可以由多位成员共同提出，保留提出人 |
| 本次共同需求 | 自住、置换或其他购房目的，预算区间、面积、区域、户型、计划入住时间、必需项、可商量项、明确排除项 | 允许成员意见不一致，保留待确认的问题。某人喜欢顶楼，全家尚未讨论时，只列在该成员名下 |
| 购买条件与阻力 | 首付或月供可承受区间、付款方式、旧房是否要先出售、决策时间、正在比较的楼盘、已放弃方案及原因、愿意改变选择的条件 | 如果“先卖旧房”是当前阻力，下次跟进去确认置换进度。首次接触不要求收入、证件或证明材料 |
| 购房机会与项目 | 一次购买目标、主负责人、协作人、候选项目及各项目报备状态、预算、阶段、意向评分、下次行动、成交或流失原因 | 同时比较三个楼盘计一次家庭机会、三条项目意向。为自己和父母分别买两套可建两次机会，各自成交核算 |

资料支持“客户亲口说、家属转述、销售观察、待确认”，并保存记录时间。遇到“房间越多越好，但最高总价不能动”时，销售能标清哪项必须满足。敏感附件进入交易资料区，按岗位授权。客户要求停止联系时，记录适用成员、渠道和范围，派单、提醒、营销发送都要检查。

**查重与合并。** 先按授权可用的联系方式、历史线索和项目报备提示疑似重复。共用电话、换号、重名都可能发生，选项包含“同一人”“不同人、同一家庭”“同一家庭、另一次购买”“无关”。只向销售提示必要信息，跨团队交给具备权限的人员核实。合并后保留原始线索、来源证据和历史贡献，误合并可拆回并复核受影响单据。

## 2. 来源、流转与客户海

| 要回答的问题 | 记录与规则 |
| --- | --- |
| 客户最早怎样进入公司 | 首次来源分自拓、公司资源、合作渠道等，可细分老带新、活动来访、广告、官网、渠道公司及经纪人。记录引荐人、首次开发人、可选的外部来源编号、发生时间和凭据。来源更正保留前后值 |
| 我怎样得到这位客户 | 单独保存“本人开发、经理分派、同事转交、公海认领、联合服务”。公司投放给甲再由甲转乙时，乙看到“同事转入”，经营报表仍可追到公司投放。自拓资源也适用同一套转交规则 |
| 此刻谁负责回电 | 每个活动机会有一名主负责人，可有协作销售、案场接待及外部引荐人。记录转出方、接收方、时间、理由、范围和接收结果。指定转交等待接收，超时提醒或回到分派队列。原负责人可看到交接状态。接收前由原负责人继续履约，首次分派无人签收时由派单经理兜底 |
| 谁为成交做过事 | 首次获客、有效报备、首访接待、复看、协作谈判和签约等贡献分别关联人员、项目和事件。员工调岗、离职、客户退海后仍按发生当时的组织和身份追溯。贡献是否计提取决于成交单适用的规则 |

**经理派单。** 支持指定销售、指定团队、批量分配或投放公海。小团队默认手工派单，大团队可按服务区域、楼盘经验、当班情况、在手量设置轮转。每条派单有签收、首次联系截止时间、超时提醒和重新分配记录。导入前验证数据、识别重复行，事后可查每一条落到了谁手里。

**销售交接。** 支持转给指定同事、邀请同事协作、主动投入客户海。投海理由包括客户要求换顾问、区域不匹配、本人无法继续服务等。“明确勿扰”进入对应范围的停止联系名单。交接时列出客户允许分享的信息、已做承诺、已有预约、未解决问题，并为新接手的人生成待办。若客户要求换顾问，可排除原负责人回领本次机会。客户提出暂缓购房时可进入培育名单，按客户指定日期恢复联系。

**分池和保护期。** 公海可设为门店、项目、城市或公司范围。待领取卡只显示接手判断需要的区域、预算档、阶段、投海原因和下次行动。领取成功后才按权限解锁联系方式。支持领取上限、归还、优先认领、保护期、到期预警和回收。有效跟进信号与续期条件由租户设定。多人同时认领仅一人成功。已认购、有未来预约或有归属争议的客户进入专门交接流程。一个家庭有两次独立购房时，投海前明确移交哪一次，其余记录按原权限保留。

**撞客处理。** 同一项目有多个报备时，展示项目规则版本、报备有效期、到访凭证与时间线。主管裁决时记录依据并通知相关人员，员工可申诉。争议只冻结相关业务的分佣部分，其他服务工作可继续。案场或财务人员登记外部回执，查阅按内部岗位授权。

## 3. 普通销售的工作台

| 销售正在做的事 | 工作台提供什么 |
| --- | --- |
| 日带看与个人工作计划 | 待签收新客、客户指定时间回电、今日邀约与带看、即将失效的报备、自己答应发送的资料、快到期的锁房，以及需要同事或经理处理的事。可完成、改期、委托并记录原因 |
| 接触和跟进 | 记录业务发生时间与录入时间、跟进人、实际沟通的家庭成员、方式、关联项目或房源、是否接通、客户原话、兴趣和异议变化、发送材料、当前进度、阶段前后值、意向评分及理由、下一步、责任人和联系时间。电话未接通也能记一次尝试，有效交流单独统计 |
| 判断意向 | 默认可用 1–5 级和“资料不足”。1 表示初步了解，3 表示已明确需求且愿意比较，5 表示已选具体房源并讨论认购条件。2、4 为中间档。销售可调整并说明。阶段、意向、紧迫程度各自记录。置换未完成的高意向客户仍可处于等待阶段 |
| 发起邀约 | 选首次到访、复看、线上讲房、洽谈或签约，记录邀请谁、发起时间与方式、目的、项目、候选时间、地点、接待人。邀约结果分待回复、接受、婉拒、待改约，写明接受或拒绝原因、客户原话、下次联系人和时间 |
| 接待与带看 | 履约另记已到访、未到、取消或已改期。保留原预约和新预约关联，分别记录实际到访人、接待人、看过的房号、客户逐套反馈、下次承诺。临时到访可以直接签到，多人一起看房按一组到访统计 |
| 帮客户选房 | 项目知识库、楼栋户型、销控更新时间、一房一价、户型图和资料有效期。支持两三套房并列比较总价、首付试算、朝向、通勤与顾虑。经销售确认后分享客户版选房单，隐藏内部底价、佣金、私有备注 |
| 协作谈单 | 呼叫经理帮谈、邀请熟悉楼盘的同事协助、交接已有预约。给案场发送项目报备，收取已通过、已驳回或到期反馈。记录谁协助、解决了什么问题，供后续核算 |
| 认购到交付 | 查可售状态、申请限时锁房、走优惠审批，跟踪认购、签约、首付款、贷款资料、放款、尾款、交付与遗留问题。换房、退订、失单分别登记，联动房源释放、待办和佣金调整。交付后可经客户同意记录老带新关系，另开机会 |
| 看自己的收入 | 按单查看贡献角色、适用规则、预估、待核、可发、已发与调整金额，看到还差的条件及经办人。能提交补充凭据、提出异议、跟踪处理结果 |

## 4. 上级可见性与团队管理

每条购房机会提供“向直属经理公开详情 / 仅共享业务摘要”。允许销售对其有权管理的记录逐条选择、授权特定同事或设置截止时间。建档和接单时明示企业规则，尤其是公司分派资源的交接义务。默认建议如下。

| 角色及场景 | 可见与可操作 |
| --- | --- |
| 直属经理，销售选择保留隐私 | 看到负责人、匿名机会编号、业务阶段、是否按时跟进、需要何种协助，以及团队汇总。姓名、联系方式、家庭成员、原话、语音和私密备注隐藏 |
| 直属经理，销售选择公开 | 可看这次购房中授权分享的客户、需求和跟进详情。联系号码、附件下载、批量导出分别授权。调换经理或停止共享后重新计算访问权 |
| 公海、协作人、原负责人 | 待领取时可看脱敏摘要。指定协作人得到完成这次工作所需字段。原负责人完成移交后保留交接回执和本人贡献凭证，其后看新记录需重新获授权 |
| 案场、财务与人事 | 案场看报备与接待所需资料。财务看合同、收款、归佣与结算凭证。人事看任职、排班和获准交付的提成结果。岗位职责决定字段范围 |
| 区域与总部 | 默认看各层级汇总。履约、客诉、离职交接等有业务依据时，可按权限申请限时查阅指定信息，记录原因、审批人、有效期和访问日志 |

企业可配置公司资源需要交接的业务字段，个人备注单独存放。企业调整规则时，应在生效前显示影响范围。通用 CRM、公海、通知预览、导出、搜索、附件和 AI 问答都执行同样的权限。成员对某位销售授权不等于同意与整个团队分享家庭资料。

**团队经理的日常工作**

- 看在岗销售、角色、负责门店和项目、值班与休假、擅长区域、在手客户量、待跟进量、转化表现、目标及替班人。支持项目临时编组、跨店协作、调岗和离职交接。经理可按日期查看团队带看安排、资源冲突、代理接待及实际到访。
- 分派资源后看谁已签收、多久联系、是否有效、需不需要换人。能对某条机会批注、派陪访、协调优惠、提醒回访、保存辅导结果。团队例会从实际卡住的机会中选案例。
- 经营漏斗按线索、有效联系、接受邀约、实际到访、复看、认购、签约和实收分别计数。接受邀约率按有效发出邀约计算，赴约率按观察期内已到期的已接受预约计算，改约链和取消原因可追查。自然到访单列。家庭机会、到访组次、到访人次、签约套数使用不同口径。
- 目标可分解到区域、门店、项目、团队和个人。按已有来源比较到访、签约和回款。按历史阶段与预期月份列预计成交，单列实际成交。查看客户积压、阶段停留、退海后再成交与逾期佣金，指标可回查权限内的业务单据。

## 5. 佣金、业绩与经营账

作为设计参照，招商蛇口公开披露了客户报备、签约或放款、成交结算单确认和审批支付。三湘印象披露了按项目采取固定比例、按完成量计提等约定，并有分期付款分次申请佣金的安排。因此，系统需要支持不同合同、计算基数与结算节点。[招商蛇口问询回复，6-1-27](https://disc.static.szse.cn/download/disc/disk03/finalpage/2026-05-12/ae82131c-ca90-4552-9ab1-3a95f269d9eb.PDF) · [三湘印象问询回复，7-2-47 至 48](https://disc.static.szse.cn/disc/disk03/finalpage/2023-07-25/4ce158a9-3189-4542-8753-dd7bf9292af5.PDF)

| 账目 | 业务口径 |
| --- | --- |
| 房屋成交与购房款 | 记录房价、优惠、购房合同、付款计划、实际收款方和凭证。自销企业可核收房款。代理公司可登记开发商确认的购房款进度，自己的应收款另立单据 |
| 公司与外部单位结算 | 代理公司向开发商收代理费，开发商自销时可能向外部渠道付服务费。管理合作主体、项目政策、报备有效性、应收或应付、对账单、发票、分期到账或付款。合同、收费方向和结算主体一一对应 |
| 内部业绩与员工提成 | 成交套数、销售额、协作业绩、个人提成各用自己的口径。按项目或活动可设固定金额、成交额比例、实收服务费比例、分档奖励和角色分配。保存规则版本、适用日期、计算基数、计算明细和确认人 |

**结佣过程。** 成交时展示预计金额。达到指定的签约、首付、到账或其他合同节点后，生成可核佣明细。分配人确认角色与份额，财务复核、按期发放，销售签收或申诉。重复回款通知不重复计提。同一笔可分配提成的份额合计须为 100%，单独的奖励或留存另列。支持分批发、尾差、跨店业绩、冻结争议份额、退房冲回和补发。规则调整后保留历史结算快照，更正走差额调整单。员工在自己的账单上能看到“为什么有这笔钱、什么时候能发、为什么少发”。

**同一单怎么算。** 假设代理项目的成交价 250 万元，合同约定公司代理费 2%，应收 5 万元。本例内部制度约定“按实际收到的代理费提取 20% 作为员工提成”，其中推荐人占 30%、成交人占 70%。公司首批收到 3 万元，这一期可计 6,000 元，分别为 1,800 元、4,200 元。尾款 2 万元到账后再计 4,000 元，分别为 1,200 元、2,800 元。另一家开发商可约定每套固定奖励。比例只用于说明单据之间怎样勾稽。

## 6. AI 如何帮助卖房

| 场景 | 输入、输出与确认 | 上线检验 |
| --- | --- | --- |
| 带看后口述建档 | 销售用自己的话复盘，或在获得授权后使用沟通材料。AI 分出“谁说的、哪条是共同需求、哪间房、约了什么”。逐项显示原话、供销售修改，确认后一次写入跟进、成员需求与日历。客户时间含糊时生成待确认事项 | 抽查成员归属与时间提取正确率，测量单次记录耗时及人工修改量 |
| 一户家庭比三套房 | 先按硬性条件与有效库存过滤，再列各成员关心的差异。预算内有两套、另一套超预算时，说明差额和取舍。只在客户愿意放宽时列替代项，价格、房态和项目资料均显示来源与更新时间 | 看候选是否违规越过硬条件，推荐是否实际用于带看，以及客户反馈 |
| 房源有变化时找客户 | 新房源释放、价格获批调整时，按权限反查曾因相应原因搁置的机会。提醒负责人为何匹配，上次承诺和勿扰状态同时展示。销售审核后自行联系 | 看有效匹配数、重复提醒、转为复看的比例及勿扰命中情况 |
| 每日待办与邀约准备 | 先列客户明确约定，再提示保护期将到、报价更新、已答应发资料等事项。每项给出理由。基于真实项目资料起草邀约，销售确认收件人和内容后发送 | 观察漏跟进率、准时兑现承诺比例和实际到访，不用消息生成量衡量效果 |
| 经理复盘与销售训练 | 例如“上月城南首次到访后未复看的家庭有哪些共同顾虑”。按权限返回分母、分类、未知项和可访问的案例。训练使用脱敏案例演练异议处理，经理可布置陪访或资料修订任务 | 核对指标与正式经营报表是否一致，验证受限内容及其摘要不会被输出 |

资料缺失时允许写“待核实”。学校划片、交付日期、贷款条件等使用企业已核实且带有效期的资料。意向建议展示行为依据和人工覆盖记录。归属裁决、价格批准、锁房和最终结佣由明确规则及授权人员执行。AI 服务暂不可用时，销售仍可手填跟进、查房、约访。

## 11. 帮助销售推进已有客户的产品设计

### 11.1 让家里没到场的人也能参与选房

销售选好两三套房，给客户一个手机浏览器可打开的家庭选房页。主联系人邀请家庭成员，各自可以收藏、排除，留下一条“我想确认的事”。一位成员可以私下保存意见，也可以明确选择分享给家人或顾问。共识只采纳成员主动分享的反馈。无需给每个人建一个销售系统账号。

假设两人都选了 2 栋 803，先生问“周六想亲自走一下地库到单元门”，陈女士问“次卧能不能放一米五的床”。AI 将这两条反馈整理成复看议程，销售约一次能解答两件事的复看。房子售出或资料更新后，比较页显示状态和版本，可换房继续讨论。试点看家庭提出的问题有多少在下次带看前得到答复，以及使用选房页的家庭实际复看情况。

### 11.2 把看房路线排成一次现场验证

销售在客户走进样板间之前，先定下“这次想验证的两件事”。比如客户在意轮椅出行，路线就从停车位走到入户门，经过坡道、电梯和门槛。客户在意书桌怎么摆，就安排查看对应房号的尺寸图，允许实测时带尺现场核验。在售项目只有样板间时，记录标明“样板间观察”，并列出实际交付仍待项目确认的地方。

App 可预约接待、钥匙或样板间时段，把客户选的时段与案场可用资源核对。看完逐项记“已实测、项目已书面确认、仍待答复”，附获准分享的材料。销售答不上来的问题直接交案场负责人，负责人补齐资料后回到原顾问，由顾问回复客户。同一版户型资料可复用，各户的私密问题分别保存。试点看承诺解答的问题逾期了多少、还有多少次复看因资料或接待资源缺失白跑。

### 11.3 为“先卖后买”的家庭倒排时间

客户喜欢新房，但首付要等旧房尾款。销售和客户只需填写本次交易所需的几个节点，如旧房签约、预计到账、可动用资金、新房认购和锁定到期。每个日期标注“合同确定、客户预计、尚未确认”，可以只录区间。

假设新房锁定到 12 日，旧房尾款预计 18 日到，系统标出按目前预计相差 6 天。销售能在同一页申请延长保留期、查询客户认可的备选房源、约定到款后再联系。项目明确不能延期时，关闭这个选项。日期运算和库存状态以业务记录为准，AI 负责把时间冲突解释给销售并草拟沟通提纲。旧房节点由客户或获授权的协作人更新。验收看临近过期前是否仍有人能处理，以及最后采用了延期、换房、继续等待还是放弃。

### 11.4 开盘前发现撞房，给落选的家庭保住第二选择

客户自愿登记第一、第二选择，以及哪些差异可以接受。经理在 PC 上看到某套房有多少家庭列为首选，有多少家庭完全没有备选。开盘前，顾问可以提前确认“如果 1202 被选了，1002 的楼层和差价能接受吗”。意向登记本身不占房。正式选房执行项目公布的顺序、确认时限与销控规则。

首选售出后，销售只收到客户已接受且仍可选的备选。释放的房号按项目确定的候补规则依次通知，客户可以拒绝或退出。真实锁定前再检查一次房态，超时释放有明确记录。AI 可以解释两套房的差异，候补顺位由规则确定。小门店只做单房号候补，集中开盘再启用志愿分布和时段安排。看首选落空后有多少家庭成功选了备选，也看有多少人收到已经售出的房号。

### 11.5 谈优惠时，让销售和经理算同一笔账

客户说“房价少两万，或者车位优惠，我就再考虑”。销售建两份可选方案，在客户侧分别列出实付总价、权益范围、使用条件和有效期；经理侧看到每种方案的实际成本、费用承担方、可用预算和审批权限。若门店承担的车位补贴成本为 8,000 元，门店直接补贴房价的成本为 2 万元，在其他条件一致时，审批人能看见两案成本相差 1.2 万元。客户是否接受其中一案仍由客户决定。

代理公司只能提交开发商允许的优惠，需对方确认的方案先显示待批。批准后形成带版本的报价，客户选用的版本随单进入签约检查。AI 起草客户版说明，金额使用已维护的价格和成本数据计算。试点看特价审批耗时、签约价与批准报价的差异、单笔实际补贴，以及发出报价后成交或放弃的原因。

### 11.6 把“哪些房卖不动”变成经理能验证的经营问题

每套重点房源看四个数：有多少组符合条件的客户确实看到了它、多少组把它加入候选、多少组实际到访、多少组最终选了同项目另一套。未推荐过的房与高曝光低入选的房分别分析。保留客户明确反馈与原因未知的样本，内部查看仅用授权范围内的聚合数据。

举例，某栋中间户经常进入预算筛选，却很少被推荐。有顾问反馈户型图尺寸不全，项目经理可以先补尺寸图，安排同一批顾问使用一周，观察推荐和实际带看是否变化。另一套带看多、放弃多，且多户明确反映客厅采光疑虑，经理可安排客户认可时段的实地复看，再决定是否需要调整展示或向开发商提价格建议。AI 归纳理由，项目经理看到样本数、对照时段、同期价格与库存变化。样本少时直接列为待查，不凭几条备注认定原因。代理公司可以把这份匿名反馈作为向开发商争取物料、开实房或调整政策的依据。

### 试点怎么选

| 业务环境 | 优先启用 | 验收问题 |
| --- | --- | --- |
| 小门店、跟进已有客户 | 家庭选房页、现场验证 | 已接触的家庭能否选出候选房，把想核实的问题带到下次复看 |
| 改善或置换客多的项目 | 家庭选房页、置换时间表、优惠方案测算 | 顾问能否在锁定到期前识别资金时间差，拿到可执行的答复和有效报价 |
| 多门店代理或大型案场 | 开盘候补、优惠测算、房源经营分析 | 能否减少首选落空后流失的客户，并让项目经理知道下一周该补哪套房的材料、开放哪个时段、找谁调整哪项政策 |

家庭选房通过顾问向已有客户定向分享的轻量网页交付，与销售 App、经理 PC 共用业务数据。试点按相近客群和观察周期比较，也记录未使用功能的原因，避免把项目热度或房价变动误算成产品效果。

## 12. 在售项目管理

销售从 PC 或 App 的「在售项目」列表进入项目，默认打开「项目概况」。销售可以直接查案场电话、确认某一期的交付标准、看当前剩余房源，也可以打开已有的 3D 沙盘向客户讲解楼栋位置。项目可以先建档，分期、房号台账、沙盘等资料到位后陆续补充。

### 12.1 项目档案与详情入口

| 详情入口 | 计划维护的内容 | 销售现场怎么查 |
| --- | --- | --- |
| 项目概况 | 项目名称、推广名与备案名、城市区域、楼盘地址、售楼处地址与导航、接待时间、开发商、代理公司、物业公司、物业类型、物业费及计费单位、车位配比、分期、开盘时间、在售状态 | 根据客户熟悉的案名搜索，进详情即可看售楼处在哪里、周末几点能接待、当前在卖哪几期 |
| 项目联系人 | 支持多人。分别登记所属单位、姓名、职责、电话、工作微信或其他联系方式、服务楼栋或分期、可联系时段、主联系人和备用人 | 报备找渠道对接人，临时带看找当天案场接待，交付问题找项目交付负责人。App 可直接拨工作电话。区分对客公开热线、内部协作联系方式和停用联系人 |
| 交付时间与进度 | 分别记录预计交付时间、合同约定的交付日期或批次口径、实际交付日期。施工与验收进展可另记封顶、施工中、验收等节点及依据。交付状态可选待交付、交付中、部分已交付、已交付。延期单记原日期、最新通知日期、原因、通知附件和更新时间 | 同盘一期已交、二期在建时，项目概况显示分期摘要。销售选定具体楼栋后看到适用批次，签约房源可追到该套合同的约定 |
| 装修与交付标准 | 毛坯、精装、其他或待核，可分楼栋或房号。保存交付清单、主要配置、选装与另付费项、标准版本、适用范围、生效时间及合同附件 | 客户问“这套是不是精装，中央空调包不包”，能点开这套适用的清单。展示家具、软装和选配项目可单列 |
| 产权与证照 | 按地块和物业类型登记物业用途、土地用途、权利性质、土地使用期限及有据可查的起止日期，关联证载主体、资料编号、预售或现售资料和覆盖楼栋 | 同盘住宅与商业配套分别查对应资料。年限或起算日期缺资料时显示待核实，并能找到核实负责人 |
| 房源销控、销售统计、3D 沙盘 | 房源台账关联项目、分期、楼栋、单元和房号。项目经理可查销售与库存，销售可浏览房表或从已关联的沙盘点楼栋 | 客户问剩余三房，直接按条件看房表。客户想知道两栋楼的位置关系，再切到沙盘，两处使用同一份项目档案 |

**一条资料适用于哪些房。** 项目层保存通用资料，分期、地块、楼栋或房号可登记例外。查询单套房时展示适用范围最具体且已核实的有效记录，同时显示出处。项目总览遇到多种口径时列明差异，例如“一期毛坯，二期精装”。维护人和最后核实时间随记录保存。对外分享仅取公开字段和已准许分享的附件。

### 12.2 在售清单、库存与经营统计

**销售查房。** 首页列出自己获授权销售的项目，支持按区域、预算、户型、面积、交付时间和装修标准筛选。项目卡显示在售批次、当前可售套数、符合客户条件的套数、有效可售房源的总价区间、最近维护时间和数据来源。项目已开售但当前库存全被锁定时，显示“在售中 · 暂无可售房”。尚未接入房源台账的项目显示“库存待提供”。销售可以直接输入房号，或按楼栋、单元、楼层浏览销控表，查询朝向、面积、价格、房态及可执行的操作。

**经营统计。** 在售项目数按获授权且存在有效在售批次的项目去重。可售房数只统计已开放、台账有效且能出售的房号。锁定、认购、签约、暂停售、待核实分别展示。经理可按城市、渠道、项目、批次、楼栋、户型和日期查看新增认购、签约、撤销、净签约、成交额、回款额和剩余可售货值。净签约按期间签约生效事件减同期撤销事件计，库存按选定时点的房号状态计。若展示累计签约去化率，分母取该批次累计正式推出的唯一房号，分子取其中仍然有效的签约房号，并同时显示分子和分母。

**维护与同步。** 每个项目指定库存负责人。自营案场可批量导入房号价表，逐套维护、定时锁定或释放库存。代理项目记录开发商回传时间、可代锁范围和确认凭据。导入先预览新增、变更、冲突与缺行，缺行需核实后再下架。正式更新保存操作人、来源、时间、版本和原因，提交成功后同步至 PC、App、沙盘、统计及匹配结果。断线重连校验版本并补齐漏掉的变更。来源超过项目设定的有效期或出现冲突时，显示“待核实”和最后确认时间，移出可售推荐。多人同时锁同一房号时只有一个请求成功，签约撤销与退款分别按审批结果更新库存与财务。

### 12.3 项目里的 3D 沙盘

玉带湾已有可旋转、俯视、近看楼栋的本地三维样例。项目档案、销控和以下后续能力均属于产品计划。

**从图片建模。** 一张鸟瞰图或沙盘照可先制作固定视角的空间概念图，也可在原图上标注可点击楼栋。有带楼号的总平面图、朝向及各栋层数后，可搭建能够旋转的三维体块沙盘。增加标准层平面、单元划分和房号对照表后，可准确绑定每户在楼层中的位置。若要贴近实景的立面，需要覆盖各侧且相邻视角有重叠的照片，或项目方提供的 CAD、BIM、建筑模型。平面尺寸、高度、被遮挡的面和实际景观以项目资料或现场核验为准。平面图只到楼栋精度时，点楼栋打开销控表，避免在未经核对的立面上标示某一户。

**场景与房源共用编号。** 每个楼栋、单元、房号都有稳定业务编号和模型映射记录。项目方发布模型前核对楼栋数量、北向、楼栋编号、单元及房号映射。模型换版时检查旧映射和未匹配项。日常价格或房态调整只刷新数据。对外展示仅使用获准共享的资料，并标清“示意效果”“项目方资料”或“实景采集”。

**验收。** 用一张明确标有楼号的总平面图和一份项目房号台账做首个真实项目。销售 A 在 PC 锁定一个房号，销售 B 已打开的 App 要显示锁定、项目可售数减一，再发锁房请求时能看到冲突。释放后恢复为可售。断开后重新连接，也要能看到最终状态。复核一次价格调整、一次认购转签约和一次跨期撤销，核对沙盘、房表、客户推荐及经营报表的数值与维护时间。模型首版验收由项目方在图上逐栋点验，有房号资料时再抽查每个标准层及非标准层。

### 12.4 日照、楼栋户型与样板间的后续计划

| 后续能力 | 销售怎样使用 | 开发前要补的资料 |
| --- | --- | --- |
| 按时间模拟日照 | 选择日期，拖动当地时间轴或播放全天，观察相邻楼栋的投影如何移动。可在同一时间对比两栋楼或同一栋不同朝向的外立面。页面标明模拟日期、时刻、时区和模型精度 | 项目经纬度、时区、真北方向、经核实的楼距、楼高、地形及周边遮挡物。只有估算体量时，仅能演示光影变化。计算到某个窗口还需准确的窗位、朝向和遮挡几何 |
| 楼栋与户型关联 | 按楼栋、单元、楼层和房号查适用的户型图，展示面积口径、朝向、面宽、进深及户型版本。可区分镜像户型、边户与中间户、标准层与特殊层 | 经确认的楼层平面图、户型图及版本、房号对应表。与销控共用楼栋和房号编号 |
| 样板间 | 在户型详情打开对应的实体或数字样板间，查看照片、视频或全景，查询开放状态、地址和可预约时段。注明展示的是哪版装修，能对照合同交付清单查看包含项与选配项 | 样板间与户型、交付标准的对应关系，获准使用的影像或全景素材，以及案场维护的开放安排 |

## 13. 整个平台离门店试用还差什么

天枢可复用通用 CRM、组织权限、审批和 AI 等基础能力，玉带湾已有本地 3D 样例。全平台的试用结果需要由销售、案场、经理和财务使用同一笔业务验收。本节是对第 10 节交付计划的补充，其中的规则与岗位分工为建议方案。

| 业务范围 | 需要补齐的功能或规则 | 能验收的结果 |
| --- | --- | --- |
| 客户与一线销售 | 落实私有客户、公海、临时协作的字段权限。把回访、邀约、带看、客户承诺放入同一份个人日程，规定何时算完成、何时需要重约、无人接单由谁处理 | 客户要求更换销售后，旧销售的回访提醒停止，新销售接到原约定，原开发人的贡献仍能对账。经理及其 AI 助手只能读到获准查看的字段 |
| 项目、案场与交易 | 明确各项目可售范围、房态确认人、案场接待队列。建立从报备、到访、报价、认购到签约的成交单，记录有效报价、材料缺项、下一位经办人和期限。改价、停售或换房时关联受影响的客户及预约 | 代理门店发出用房申请后显示待确认，收到有权案场的回执才更新为锁定。已约房源停售时，负责销售接到改约任务，经理可看到处理结果 |
| 团队管理与 OA | 把目标、在手客户和待办负荷用于派单。在审批单上明确申请人、代理人、超时处理、回写结果和失败重试。设置休假代班及离职交接清单。经理能从掉单原因创建陪访、协调或培训任务并跟踪结果 | 销售临时请假，经理能把周末带看交给值班同事。接待人只获得本次资料，自己的协作记录有据可查。优惠获批一次，成交单上的批准价格只更新一次 |
| 财务与公司经营 | 为自销与代理分别定义结算主体和收入来源。用一笔历史成交核对房款、代理费、渠道费、个人提成及费用。规定跨期退房、离职待发、异议和差额调整由谁核准。按门店、项目和渠道归集直接成本 | 老板能同时查签约额、公司应收未收、实际到账与项目直接贡献。财务能从员工账单追到有效结算单，跨月退房有调整记录 |
| 客户成交后服务 | 签约时交接贷款资料、待履行承诺、交付和客诉经办人。代理公司可将问题转开发商，跟踪对方回执、客户回访及是否解决。获准转介绍后，生成新机会并保留引荐关系 | 原销售离职后，客户仍能查到当时答复和当前经办人。同类交付问题可汇总给项目负责人处理 |
| AI、资料与权限 | 首版选定口述转跟进及 AI 根据有效库存筛房的试用样本，核对家庭成员归属、日期金额、依据和权限。资料更新可让 AI 提出差异，负责人确认后发布。为错记、过期数据和服务不可用准备可操作的纠正路径 | AI 将成员偏好写错时，销售可改单项。源房号停售后停止推荐。拒绝联系的客户不会因 AI 建议再次进入联系队列 |
| 租户上线与集团推广 | 给小公司提供默认角色、保护期和佣金模板。支持导入历史客户、负责人、未完预约与未结佣单，按条返回异常。集团扩展到跨店协作、多法人结算、总部规则继承、审计与高峰容量验证 | 新门店首日能接续原有业务。跨店只分享本次协作资料。同一笔签约在总部汇总只算一次，店间贡献按既定份额显示 |

**首轮试点。** 选一家门店和一个项目，准备脱敏的存量客户样本、一份可售房表及一笔已结佣历史订单。销售在 App 完成接客、邀约、带看和跟进确认。经理在 PC 派单并办理一次换人或优惠审批。案场确认房态，财务按实际到账复核分佣。再演练一次停售改约或跨期退订，逐项核对接手人、客户可见资料、房态、报表和提成。门店记录原来与试用后的录入耗时、漏约和对账差额。

**扩展顺序。** 首轮先跑通一家门店的客户、项目、交易和结佣，再完善售后工单和跨店经营。集团试点再验证多法人、规则继承和万人规模的高峰业务。日照模拟、楼栋户型和样板间沿用第 12.4 节的后续安排。
