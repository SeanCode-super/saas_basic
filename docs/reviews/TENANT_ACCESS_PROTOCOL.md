# TenantAccessContext 与平台旁路协议

状态：`Implemented in M0`

## 1. 目标

普通业务请求的租户只能来自认证会话。请求头、查询参数、请求体和前端状态都不能改变服务端租户边界。

## 2. 上下文模式

| 模式 | 来源 | 可访问范围 |
|---|---|---|
| `TENANT` | 已验证会话，或登录后已解析的租户 | 仅当前 `tenant_id` |
| `SYSTEM_BYPASS` | 认证令牌定位、公共门户定位 | 仅允许预定义基础设施操作 |
| `PLATFORM_BYPASS` | 平台身份、显式权限、操作类型和原因 | 经授权的跨租户平台操作 |

上下文使用可嵌套的 `AutoCloseable` 作用域。退出作用域时恢复上一层上下文，请求结束时必须清理 ThreadLocal。

## 3. 强制规则

- `TenantLineInnerInterceptor` 为租户表的查询、更新和删除追加 `tenant_id`。
- `MetaObjectHandler` 在租户实体写入时用当前上下文覆盖调用方提供的 `tenantId`。
- 没有上下文访问租户 Mapper 时返回 `TENANT_CONTEXT_REQUIRED`，不回退到平台租户。
- `plat_tenant` 和 `plat_tenant_package` 是当前仅有的无 `tenant_id` 平台表。
- 受保护请求只发送 `Authorization`，不发送 `X-Tenant-Code`。
- 登录请求可以提交租户编码，但必须先解析为有效租户，再建立租户上下文。

## 4. 旁路约束

旁路必须同时包含：

- 固定枚举操作类型
- 非空原因
- 操作者 ID；系统操作使用 `0`
- 平台旁路所需的权限码
- 平台身份校验

当前允许的系统操作只有：令牌所属租户定位、公共门户所属租户定位。租户初始化使用平台旁路，并要求 `tenant:write`。

新增旁路操作必须经过安全评审，不能通过布尔参数、请求头或 Mapper 注解临时关闭租户拦截器。

## 5. 审计要求

- 平台写操作必须写操作审计，记录操作类型、原因、操作者和目标租户。
- 高频令牌定位不逐次写业务审计表，但必须进入认证指标和异常安全事件。
- 公共门户定位只允许读取公开配置，不得在旁路作用域内返回租户业务数据。
- M2 将为平台跨租户操作增加独立权限码和统一持久化审计切面。

## 6. 自动验证

- Mapper 实体矩阵验证所有租户表实体都暴露 `tenantId`。
- 迁移矩阵验证无 `tenant_id` 的表只能来自平台表白名单。
- MySQL 集成测试验证伪造写入、跨租户按 ID 读取、跨租户更新和无上下文访问。
