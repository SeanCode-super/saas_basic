# 天枢平台修复与回归报告

2026 年 11 月 20 日，本地开发环境。本轮处理上一轮报告列出的权限、审批、业务单据和运行状态问题，以及应用按租户发布至 PC、手机的能力。业务写入和浏览器操作使用独立的 MySQL、Redis 和临时账号。开发库只执行正式迁移和维护者确认的历史单清理。

## 已从用户入口验证

| 场景 | 操作与结果 |
| --- | --- |
| 原表追加字段 | 发布设备点检表，先录入“QA水泵”，再追加“点检说明”。相同请求重试后只保留一个字段，原记录仍可打开、补写。PC 和手机 H5 都登录并打开了这条历史记录。日期类型也在独立 MySQL 测试中经过读写。 |
| 员工按应用填报 | 给普通角色分配点检菜单和该模型的新增权限。同一账号在没有代码工坊写权限的情况下成功提交并读回自己的记录。新增、编辑和删除可分别授权。撤销原管理员角色后，现有会话再次查询身份时已失去管理员权限。 |
| 审批退回和会签 | 发起点检整改申请，退回发起人，在途时修改流程定义，再重新提交。申请回到原审批节点，经原审批人办理后，业务状态为已通过，引擎活动任务数为零。另一笔单从第二节点退回真实历史节点，重新流转后加签。第一人签完单据仍在途，第二人签完才办结。 |

| 第三方嵌入 | 登记测试清单，为 PC、手机分别设置入口。发布下一修订后，未升级的租户仍读取原清单。升级、停用、恢复后，双端目录均按相应修订和开通状态更新。测试使用占位 HTTPS 地址，验证范围到平台目录与授权。 |

| AI 和物理隔离 | 模型凭据缺失、训练服务未接入的测试均得到 HTTP 503。申请物理数据库隔离时返回明确错误，复查租户台账保持原隔离模式。 |
| 运行指标与数据源 | 仪表盘按实际租户、数据源、任务执行日志、已发布模型取数。登记数据源时即使提交“通过”，初始状态仍为“未检测”。在同一测试端口开启、关闭监听，实际探测依次返回通过、失败。修改主机地址后恢复为“未检测”。此项验证 TCP 可达性，数据库登录与业务 SQL 需另行验证。 |

## 修复落点

- 原生扩展通过 `TenantApplication.workspaceFields(revision)` 公开已安装修订的字段。平台在读取目录时同时检查租户订阅、到期时间和角色权限。既有自定义 PC 组件可以继续使用，旧 JAR 接入通用手机页面时需要实现字段契约。[扩展开发说明](../DEVELOPING_INDUSTRY_APPS.md)
- 动态模型保留已有物理表。新增字段允许旧记录留空，锁定模型元数据以串行发布，数据库列和字段定义不一致时返回冲突。为已有已发布模型补登记可分配的记录操作权限。[模型服务](../../server/saas-basics-module-codegen/src/main/java/com/saasbasics/platform/modules/codegen/service/AiAppBuilderService.java) · [数据操作权限](../../server/saas-basics-app/src/main/resources/db/migration/V89__dynamic_model_record_permissions.sql)
- 新审批实例保存发起时的流程和表单定义。退回任务记录来源，办理前锁定业务实例，办结时核对引擎回执。真实数据库测试还发现并修正了员工关联字段，现按同租户账号的员工 ID 查找部门。[办理服务](../../server/saas-basics-module-workflow/src/main/java/com/saasbasics/platform/modules/workflow/service/WorkflowTaskService.java) · [员工与角色查询](../../server/saas-basics-module-workflow/src/main/resources/mapper/WorkflowParticipantMapper.xml)
- 数据源登记的检测状态、AI 训练结果和业务凭证均按可核对的事实展示。文件绑定的存储源失效时拒绝读取，无处理器的 Outbox 事件进入失败处理，API 计数在数据库写入成功后才推进游标。Compose 和 Helm 的生产配置已包含数据库装配，前端上游可按部署服务名设置。[数据源服务](../../server/saas-basics-module-integration/src/main/java/com/saasbasics/platform/modules/integration/service/IntegrationService.java) · [生产部署配置](../../docker-compose.prod.yml)
