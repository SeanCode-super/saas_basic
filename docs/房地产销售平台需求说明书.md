# 天枢房地产销售平台需求说明书

版本 1.2 · 2026-11-28 · 适用场景为新房自销、开发商委托代理、门店联合销售。交付端包括天枢 PC 工作台、员工 App 和面向已邀请家庭成员的选房页。本文可单独交给能访问天枢仓库的开发者或编码模型。业务目标、操作规则、数据契约、仓库既有约束和验收用例均在文内。

**v1.2 修订要点。** ① 私密机会进入审批、报备、认购后，按交易环节向必要岗位开放最少字段，避免“仅摘要”卡死审批和财务。② 新增 FR-20 认筹排号与集中开盘选房、FR-21 个人信息与销售合规。③ 补充报备撞单裁决、迟到宽限与爽约更正、认购违约与定金处置、按揭节点、代理项目不代收房款、车位等非住宅房源、一房一价校验、佣金异议、通知失败降级、恢复目标。④ 修正样例接口用房号代替内部 ID、阶段与 FR 映射不一致、U21 过长等问题，新增 U23–U25。⑤ 第 8.1 节已于 2026-11-28 抽查确认：迁移最高 V93；`approveReceivable` 无事务和状态校验，会直接改为已核准；`returnCustomerToPool` 清空客户主档负责人；`AiGatewayFacade` 仅有文本 `complete`；移动端 `npm test` 仅含两项脚本。其余条目开工时仍须复核。⑥ 新增 FR-20、FR-21 后工作量增加，排工表需补 C07、C08、A05 并重估人日。

## 1. 平台定位与交付范围

**可直接对外介绍**

天枢房地产销售平台致力于帮助销售顾问为每个购房家庭找到合适的房子，也让公司管好一笔成交背后的协作和账。同一个家里，有人在意上班路程，也有人需要从车库坐电梯直达家门。顾问可以用 AI 整理这些需求，从当下可售的房源里选出值得带看的几套，看完记下还要替客户确认什么。即使中途换了顾问，之前的约定也有人接着办。从一家门店到跨城市的团队，负责人都能查清房子卖到了哪一步、款收了多少、佣金该分给谁。

| 发布范围 | 要交给谁、做到什么程度 |
| --- | --- |
| 门店试点 A–D | 销售、经理、案场、财务和客服用同一笔业务完成建档、邀约、带看、报价、认购、签约、回款、结佣和售后交接。在售项目提供项目档案、维护后的可售房表及可交互 3D 入口。AI 提供口述建档和按有效库存匹配家庭需求。 |
| 城市多店 E | 跨店协作、归属争议、经营账、完整 OA 与售后、受邀家庭选房、置换倒排、候补和优惠方案比较、房源经营分析。 |
| 集团 F | 多级组织和多法人、政策继承、总部经营、财务薪资对接、租户灰度与万人规模验证。小门店沿用同一产品，可只开所需模块。 |
| 本期范围外 | 获客与渠道运营，包括广告投放、获客活动、公开留资页、外部渠道自助门户、获客成本与投产分析。已有客户的原始来源、公司派单、同事转交、内部案场报备、内部登记的合作单位主档与合同约定对外结算均属于本期。 |
| 后续储备 R | 按日期与当地时间模拟日照，精细楼栋/单元/户型及房号空间定位，数字样板间/全景及预约。保留项目与资源编号。三个专项独立排期，本轮不做功能入口或模拟数据。 |

**试点成效**由门店记录使用前后的带看后归档耗时、按约回访率、赴约率、从实收到核佣的时间和对账差额。比较时列出期间、样本、价格与库存变化。经营指标用来观察实际效果，不能替代功能验收。

## 2. 角色、数据权限与双端入口

| 使用者 | 主入口与动作 | 可见范围 |
| --- | --- | --- |
| 销售顾问 | App「今日工作」「我的客户」「日带看」「在售项目」「我的收入」。PC 可补录、筛选、对比、交接 | 本人负责的购房机会，可操作获授权的协作事项。对每次机会设置向直属经理公开详情或仅共享摘要。可看本人贡献及结佣进度。 |
| 门店经理、城市经理 | PC「团队日历」「人员与分客」「目标与漏斗」「待审批」。App 接收代班、审批和求助 | 可查下属任职、项目、负荷、到访和进度。私密机会只返回匿名编号、责任人、阶段、逾期及脱敏求助类别。公开详情后，号码、附件、导出仍各自授权。 |
| 案场接待、项目维护人 | PC「报备与接待」「项目档案」「销控与价表」「模型绑定」。App 查当班、签到、补回执 | 只看授权项目的接待或资料。接待员确认到场，库存维护人确认价表与房态。具体权限可分给不同人员。 |

| 法人负责人、总部经营、租户管理员 | PC「经营报表」「规则与组织」「应用开通」「审计」 | 负责人看获授权组织的汇总。跨店查具体事项需显式授权。应用管理权限本身不授予查看客户原话、私人电话或财务明细的权利。 |
| 受邀家庭成员 | 手机浏览器「家庭选房单」。查看指定房源、标记喜好、填写待确认问题、选择反馈共享范围 | 凭受邀身份访问指定选房单。页面只读已准许发布的字段。成员可选仅自己、对顾问、对本组共享。撤销或到期即时结束后续访问。 |

**授权顺序与隐私边界。** 服务端依次检查租户和应用开通、岗位动作、组织/项目范围、机会授权及字段权限。销售的共享开关以机会为单位，并区分来源属性：自拓机会默认允许设为“仅摘要”；公司派单或公海认领机会受租户配置约束，至少向直属经理开放约定的履约与交接字段（如阶段、下次跟进时间、预约状态、逾期预警），个人私密备注与原话仍单独控制。客户主档被多个机会引用时，联系资料按当前访问目的授权，私有跟进不能借共享的另一笔机会查询。销售选“仅摘要”时，服务端对列表、详情、原有 CRM、搜索建议、导出、下载、通知、AI 检索和日志展示执行相同裁剪。**搜索私密机会严禁“先匹配后脱敏”**：当无权查看详情时，按客户姓名、电话、微信号或备注关键词检索必须在查询条件层直接排除该记录（仅允许按匿名机会编号、责任人、阶段检索），防止通过命中结果反推客户身份。

**交易环节的最少必要披露。** “仅摘要”只约束跟单阶段的私人资料，不能阻断公司流程。机会进入以下环节时，按环节向经办岗位开放最少字段，其余私密备注和原话仍不可见：提交优惠或特殊审批时，审批人可见房号、报价版本、申请理由、客户称谓和意向依据；提交报备时，案场可见报备所需的脱敏号段和到访信息；认购后，案场、财务、客服可见买受人主体、合同及付款所需资料；发生归属争议时，裁决人按审批的临时查看规则访问。销售在发起这些动作前，页面提示将向谁开放哪些字段。

**联系方式存储。** 手机号、证件号等高敏字段加密存储，查重和精确检索使用租户内加盐的哈希索引，列表默认脱敏显示。模糊检索只对有权查看的机会开放。

**转交、临时访问与审计。** 公司资源在签收前向接单人明示履约所需字段、可见人和期限。销售可授权指定同事参与一次带看：客户联系方式与历史资料随预约结束/截止时刻自动收回；为避免现场结束后无法归档，代班同事对**本次接待单自身的逐套反馈与复盘草稿**保留可配置的提交宽限期（如预约结束后 24 小时内可补交，超时锁死且期间不可查看客户历史全量资料）。交接、调岗、离职、取消分享后即时重算权限并触发移动端本地敏感缓存与离线草稿撤权清理。需处理客诉或离职交接时，由获授权负责人审批临时查看，保存申请人、用途、字段、期限和查阅记录。查看私密号码、临时越权查阅、导出报表、修改成交价、人工拆并客户、手工覆盖房态和调整已发佣金均强制写入不可篡改审计日志。小店兼岗按当前操作身份审核，金额和跨法人操作遵循租户的审批设置。

## 3. 销售工作和客户关系

**FR-01　个人、家庭与购房机会。** 新建个人客户至少填写称呼，记录原始来源。手机号、家庭成员和家庭财务资料按实际掌握程度补充。可直接为个人建立购房机会，之后再关联家庭。家庭支持亲属及非亲属共同购买，一人可兼具联系人、出资人、决策人、居住人、签约人等角色。没有联系方式的成员可以只填“母亲”等称谓。一次购买建一个机会，可对比多个项目。一个家庭买两套且分别决策时开两次机会。一个项目成交后，其余候选记作未选。

| 录入区域 | 字段与校验 |
| --- | --- |
| 联系与意愿 | 称呼、电话或其他联系方式、偏好方式、可联系时段、勿扰成员/方式/范围、生效时间、可选的恢复日期。显示来源和最后核实时间。 |
| 成员兴趣与共同需求 | 一条偏好关联一或多个提出人，或明确为本次共同需求。记录区域、总价区间、首付/月供承受区间、户型、面积、楼层、朝向、通勤、无障碍、车位、宠物或其他生活需求。标记必需、偏好或排除，来源为本人原话、转述、观察或待确认。预算上下限同币种且下限≤上限。 |
| 购房条件与跟单 | 目的、付款方式、计划入住/决策日期、旧房出售及回款依赖、竞品、已看与已放弃房源、卡点、主责、协作、阶段、意向及依据、下一步和截止。共同结论须明确确认。意见冲突时并列保留。 |
| 身份查重 | 按授权联系方式或外部业务编号提示疑似重复，由有权限者选择同一人、同家庭不同人、同家庭另一次购买或无关。禁止仅因同电话自动合并。人工合并保留原编号、来源、贡献及时间线。误并拆回设保护边界：未发生认购或核佣前可完整拆回并重算关联；已产生认购、签约或已核佣单据禁止直接物理拆档，须通过经审批的“跨单关联修正/归属调整单”处置并标记受影响交易复核。 |
| 买受人合规材料 | 意向阶段严禁强求证件与收入证明。进入认购与按揭预审环节后，按项目要求登记买受人、共有人及委托代理人主体的身份、购房资格核验（限购/套数/社保状态）、征信与贷款预审结论及欠缺项。高敏证件与附件加密存储，仅限授权交易、财务及客服人员按用途调阅。 |

**FR-02　派单、转交、公海与贡献。** 原始来源、取得方式、当前服务人、历史贡献分别记录。例如，甲将自己开发或公司分派的客户转给乙，乙的取得方式均为同事转入，但原始来源各自保留。公司导入、存量 CRM 线索转化或派单可以补来源编号及证据；需要对外按合同结算的转介/合作机构，在内部维护精简的「合作单位与引荐人主档」（含结算主体与合同编号，不提供外部登录门户）。一次来源更正保留前后值和经办人。个人档案中展示主责及历史联系人，分派、保护期和公海流转均**以购房机会为粒度**执行。

经理可指定人、指定团队、批量投海或按当班/区域/在手量轮转。指定转交有待签收、已签收、拒收、超时、撤回等记录。签收前原主责履约，首次无人接单由派单经理负责。主动投海要选池、写原因、列未结承诺。已认购、存在未来带看或归属争议时须先指定经办人承接相关事项。**一户多机会时，仅将指定机会投入机会公海，不得连带清零同一客户主档下其他销售仍在跟进的机会；仅当该客户名下已无任何活跃私海机会时，才允许同步标记主档可进入公海，旧 CRM 客户级退海接口遇到多机会客户必须拦截并提示选择具体机会。** 公海可按店、项目、城市或公司分池，规则含保护期、续期依据、领取上限和回收条件。两人同时领取仅一人成功。客户要求更换顾问可排除原人回领。明确勿扰后阻止对应范围的派发联系任务和触达。原顾问可查交接回执与本人贡献，其他机会和转交后的私密记录仍按新权限。

**FR-03　跟进与意向。** 每次跟进保存发生时间和录入时间、操作人、实际沟通成员、方式、关联机会/房源、是否有效沟通、客户原话或摘要、兴趣与异议、阶段变化、意向依据、下一动作和责任人。可补录，补录留操作者。未接通可记尝试。意向分为资料不足或 1–5 级，1 为初步了解、3 为明确需求愿意比较、5 为锁定具体房源并谈认购，2/4 为中间状态。意向、紧迫性和实际成交阶段分开保存。待跟进事项需填时间或标记“客户暂缓/待定”及原因。

**FR-04　邀约、日带看与个人计划。** 销售在客户详情或今日工作发起初访、复看、线上讲房、洽谈或签约邀约，选择参与人、方式、目的、候选时间、地点、接待人及关联项目。邀约可为待回复、接受、婉拒、待改约，填写成功/失败原因及下一次联系安排。接受后生成一个有效预约和对应日程。只有看房预约进入日带看。计划支持日/周视图、自建任务、经理指派、全天或定时、优先级、提醒、委托、完成、转次日及结果，并自动汇入**报备即将到期、锁房临近失效、定金/首付应收逾期及按揭材料截止**待办。

预约可含多个家庭成员、项目站点和房号。预约主销售、接待人、经理指派代班人在同一时段（含租户配置的项目间路程缓冲）撞档时均校验并提示冲突，允许换人或改期；独占场地时段冲突则拒绝重复占用。**仅在原约定时间之前发起的改约延续当前预约链**，产生新节点、关闭旧提醒并保留旧日期和原因；**一旦超过约定时间未履约（爽约），当前预约链锁定为“逾期未到”完结**，后续重新约访须生成新的预约链，避免覆盖历史逾期记录。“超过约定时间”指约定开始时间加租户配置的迟到宽限（默认 30 分钟），宽限内到场仍记实到并标迟到；客户在约定时间前已通知改期、但销售超时才录入的，可凭沟通记录补登“到点前已改约”，由经理确认后改判为延续原链，修正过程留痕。代班只授本次权限与复盘宽限期。实际接待分别登记到访、未到、临时取消、线上完成，记录实际起止、到场人、接待人、逐套反馈、待答问题与回访承诺。自然到访可直接登记。销售请假、房源停售、客户要求延期时，系统列出受影响事项并指定接手人。日历、今日工作、客户时间线引用同一业务记录。

**FR-05　定向选房与谈单工具。** 顾问从已核实、允许分享的在售房源中选两三套，生成有失效时间的家庭选房页，可撤销。**选房页采用不可枚举随机短链，配合受邀人手机尾号或短信验证码轻量核验、只读防扩散水印及限期/撤销即时拦截，无需为家庭成员建立内部员工账号。** 家人分别收藏、排除、提交现场问题。内部底价、提成和私密意见不可外发。顾问可把获准分享的问题排成复看路线，分派给案场并记录实测、书面确认或待答。置换时间表记录旧房到账、新房认购和锁定到期，日期区分合同确定/客户预计/未知，显示时间差和可执行的延期、备选或改约。候补按项目规则及有效登记顺序通知客户已认可的备选，登记不占库存。优惠比较并排显示客户实付、权益、限制、有效期，经理额外可见承担方、成本、预算和审批权。

## 4. 在售项目、案场与交易

**FR-06　在售项目档案。** PC 可建档、维护、提交核实和发布资料。App 与 PC 可按案名、区域、批次、可售总价/面积/户型、交付日期及装修筛选。项目可先建档再补库存和模型。默认打开概况，从同一项目进入联系人、交付与产权、房表、销售统计和 3D。维护人、来源、适用范围、版本和最近核实时间随资料展示。

| 资料 | 最小内容与适用规则 |
| --- | --- |
| 概况与联系人 | 推广名、备案名、城市、区域、售楼处和楼盘地址、导航、营业时间、开发商/代理/物业、分期、开盘及销售状态。多人联系人分别登记单位、职责、工作电话/其他联系方式、适用分期、联系时段、备用人及内外部可见性。 |
| 交付情况 | 分开保存预计、合同约定、实际交付日期。记录施工节点、依据、待交付/交付中/部分已交/已交。延期保存原日期、通知日期、原因、凭据及适用批次。 |
| 装修、产权与证照 | 毛坯/精装/其他/待核，交付清单、包含或选配、版本和适用范围。地块、物业/土地用途、权利性质、使用期限及有凭据的起止日期、证照编号、覆盖楼栋、附件和核实人。 |
| 层级差异 | 单套合同交付约定独立保存。查具体房号按适用的已核实有效资料，从房号、楼栋、分期或地块到项目通用值取值。同层级有冲突列待核，多个分期口径不同则在项目概况分别列示。 |

**FR-07　房源、销控与同步。** 房源有稳定内部 ID 和项目方编号，区分产品类型（住宅、车位、储藏室、商铺、公寓等；车位和储藏室可无楼层户型，按区域编号管理，可单独成交或与住宅组合成交并分别计价、计佣），关联分期、楼栋、单元、楼层、房号、基本户型文字、朝向、面积及口径、币种、单价、总价、价表版本、批次、房态、来源与核实时刻。项目指定有权维护人、核实有效期、可售范围和自销/代理模式。导入预览区分新增、变价、状态冲突、缺行。缺行进入核查，不能直接下架。人工确认后发布新版本并通知双端刷新。项目可登记备案价（一房一价）及允许的浮动规则；发布价表或审批优惠时，成交价超出备案价或允许下浮区间的，系统阻止发布或提交，并提示需开发商重新备案或另批。**外部台账失联、过期或发生状态冲突时按房源所处交易环节分级处置**：① 未锁/未认购的可售房保留上次确认值及时间，标记“待核”并移出可推荐和可锁范围；② 已锁未认购的房源向主责销售与库存维护人发异常告警，冻结转认购直至完成人工核验；③ **已进入认购或签约中的房源严禁静默覆盖或改回可售**，须保留原交易事实、即时阻断后续网签或重复锁定，并生成高优冲突核查单交案场及经理裁决。权威交易回执才能改变已认购或已签约的事实。

项目已开售但有效可售数为 0 显示“暂无可售房”。无房源台账显示“库存待提供”。不完整或过期的台账注明待核数量。PC、App、3D、统计和推荐使用同一房态服务。维护提交后推送版本，断线重连补差或重取快照。有权销售的项目、开放批次、已核实且未过期的可售房号构成候选集。价格变化重新核价，停售自动生成已约带看、有效报价及定向选房单的处理事项，由责任人回复客户。

**FR-08　交互式 3D 沙盘。** PC 鼠标和 App 触控均能旋转、缩放、平移、回到俯视角、点选楼栋并联动真实房表。使用有深度的三维几何和相机。单张沙盘照片可作示意体量参考，未经确认的楼号、朝向、高度、遮挡或户位保留“待核”，界面说明精度。模型保存资产版本、项目、节点与业务楼栋 ID、核对人和发布状态。换版前列出丢失/重复映射，已核对的楼栋可发布。房态变化更新数据层。模型缺失、机型无法渲染时仍可查同一房表。玉带湾现有 WebGL、GLB 可作首个联调样本。每个项目使用自己的模型与绑定。

**FR-09　报备、接待与锁房。** 每个机会可向多个获准项目分别报备，支持脱敏号段（如前三后四）+ 预计到访时间 + 现场核销码/到访确认单，记录有效期、保护规则（支持项目级“先报备先带看优先 / 有效带看保护 N 天 / 自然到访 M 天防切客”模板）、提交人、回执、驳回原因、归属争议与裁决依据。报备过期未到访自动失效并提醒提交人，可在规则允许时重报。**撞单判定**：同项目内同一号段已有有效报备时，新报备进入待裁决而非直接驳回；判定顺序为项目规则模板 → 有效带看凭证时间 → 报备时间，裁决结果、依据和裁决人写入报备记录，并触发 FR-12 的份额冻结或确认。客户自行到访但处于他人有效保护期内时，接待员登记为“保护期内自然到访”，通知原报备人，不自动转移归属。案场可排队接待、签到、登记自然到访与代班。自销可由授权人限时锁房，代理项目只能按授权范围向有权案场申请。待回执只显示“已申请，待案场确认”。确认提供凭据及期限才形成有效锁。并发争房只容许一个有效锁。到期释放前重核是否已认购或有更新回执。代理库存失去权威确认时按 FR-07 分级处置。归属争议只冻结有关份额，正常客户服务继续。

**FR-10　成交单、付款计划与变更。** 成交单关联机会、项目、房号、批准报价、主责、买受人与共有人主体、合规材料缺项与下一位经办人。优惠超过岗位权限或需开发商确认时进入 OA 审批。客户接受的报价固定币种、应付总价、权益、有效期和版本。**认购确认后按项目条款生成分期应收计划**（诚意金/小定、定金、首付款、按揭放款、尾款各期金额、到期日及超期预警规则），用于个人工作计划催办和财务账龄核对。认购或签约时核实房号可交易、无未决冲突告警、报价与审批仍有效。签约写合同凭证与成交事件，并明确跨店成交时同步给关联 CRM 商机的阶段与主归属规则（退订撤销时同步回退商机及客户成交标识）。

**收款主体。** 自销项目按项目配置的收款法人和账户登记房款；代理项目的购房款由开发商收取，本系统只登记开发商回执的付款进度，不作为本公司收款，也不得生成本公司房款收据。

**认购违约与超期。** 认购后超过约定签约期限未签约的，系统在期限前提醒，到期生成违约处理单，由经理选择延期（走审批）、转退订或按合同处置定金。定金的退还、转房款或不予退还分别记录依据和审批，库存在处置生效后才恢复可售。**按揭节点**按资料齐备、银行面签、审批通过、放款四个节点记录，放款与付款计划中的按揭期核销；按揭被拒时生成处理单，可转其他付款方式或退订。

换房、退订、撤销、延期、退款各自保存申请、批准、业务生效与凭证。**换房采用两阶段安全锁**：提交换房申请期间原单原房保持保留锁不提前释放，先对目标新房发起限时锁定；若新房锁定失败，原单保持有效并转待处理；若新房锁定成功，待换房审批通过且成交变更生效后原子释放原房，审批驳回或超时则自动释放目标新房。退款到账、撤销合同和恢复可售分别确认。任何变更都能追到原单，过期回执不能覆盖新版本。

## 5. 团队、OA、财务与成交后服务

**FR-11　团队经营与 OA。** 经理能查下属任职、门店/项目编组、当班情况、在手机会、待联系数、日历、超期承诺和实际带看。按总部、区域、门店、项目或个人分解目标。例会上可从授权范围内的卡点建陪访、帮谈、补资料或培训任务，指定责任人和复盘时间。员工入转调离触发客户、预约和审批交接。原组织业绩用发生时的组织快照。经理看不到的客户，待办以匿名编号显示。

| OA 单据 | 发起、审批与落账 |
| --- | --- |
| 请假、代班、外勤、出差、费用报销 | 提交时间段、事项或费用、相关项目及凭证。请假获批后列出受影响预约和承诺，由经理确认代班。报销核准后按费用归属计入项目或门店。 |
| 特价、保留延期、换退、归属裁决、特殊分佣 | 从业务单发起，附业务版本及理由。工作流支持通过、驳回、撤回、授权代理、超时提醒。审批结果与业务生效分别展示，回写失败进入可重试队列。 |
| 项目预算、供应商、合同用印、发票与付款 | 记录结算主体、费用承担方、预算占用和付款进度。发票到账或已批准付款各有独立凭证，财务可核对。 |
| 公告与制度签收、会议行动项、培训 | 有发布范围、接收人、截止与签收状态。会议和培训产生的行动项进入个人计划，经理可查结果。 |

**FR-12　应收应付与员工分佣。** 建立三类关联账。第一类是房屋成交价、购买方付款计划与实际收款方。第二类是本公司按合同应收代理费、应付外部服务费、发票和实际往来。第三类是内部业绩与员工提成。自销企业按实际房款收款，代理企业记录开发商已收购房款进度时不得增加自己的现金。款项按租户、法人、币种、合同、回款/付款凭证和分期核销。财务可查看未到款金额、账龄及差额。

规则支持每套固定额、成交额比例、实收服务费比例、分档奖励、角色分摊、单列奖励或留存。项目政策含适用对象、生效区间、**计佣基数口径**（明确房屋净成交额/实收服务费是否扣除车位、装修包、代收税费及门店承担的让价补贴）、**计提与放佣触发门槛**（如认购定金不计提，须达到网签/约定首付比例或代理费实收到账）、**分档跳档口径**（累计跳档仅适用新增单还是追溯补差，退房回退套数时同步重算补差）、计算顺序、比例、舍入及尾差接收角色。单份可分配金额的受益份额合计必须为 100%。按财务签认的规则时点锁定版本、贡献人及组织，成交预计、待核、可发与已发分别记账。到账可分批计提，发放可分批，财务复核后才能入发放批次。调岗或离职仍保留本人历史应得。归属争议冻结涉争份额，财务按原明细做负向冲回或补发。**先发后退或跨期冲回**按项目策略先扣减本人尚未发放/冻结余额，不足部分形成个人可追踪负向欠款台账（用于后续佣金抵扣或财务追缴，严禁直接篡改已发历史凭证）。关账后新增调整记入开放期间并引用原期，保留原已发金额与差额去向。导出薪资、接收成功/失败回执、重送和核销按批次对账。**代理费结算节点**按与开发商的合同配置（如网签后结、回款比例达标后结），系统按节点生成应收代理费并跟踪对账单和开票。**员工佣金异议**：员工在“我的收入”可对某笔计提或发放提出异议，选择原因并附说明，由财务在约定时限内答复；异议期间不阻塞其他明细，处理结果若需调整按冲回/补发执行。

**结算标准样单。** 成交价 250 万元，公司代理费 2%，应收 5 万元。测试规则按实收代理费的 20% 提取，推荐人 30%、成交人 70%。首收 3 万元，计提 6,000 元，两人分别 1,800、4,200 元。再收 2 万元，计提 4,000 元，分别 1,200、2,800 元。若两期已发，下期确认退回代理费 1 万元，则新增调整 −600、−1,400 元。累计净应得分别为 2,400、5,600 元，原两期发放凭证保持原金额。上述比例仅为开发数据，实际租户启用经财务确认的规则。

**FR-13　成交后服务。** 签约后按项目模板生交接清单，包含购房合同、付款/贷款资料待办、带看时答应客户的事项、交付节点、责任人与期限。受理问题可派给内部客服或转开发商，内部经办人跟回执。工单经过受理、处理中、待外部、待回访、解决/关闭。超时升级，未解决可重开。客户同意转介绍或再次购房后另建机会并保留关联。门店能按项目查看重复问题和处理时间。

**FR-14　报表及指标口径。** 个人、门店、区域和总部使用同一指标定义。支持按组织、销售、项目、分期、楼栋、基本户型、已有来源和期间筛选，钻取仍需业务权限。零分母显示“无样本”。按业务发生时间和业务时区归日，组织调动后保留历史归属。

| 指标 | 定义 |
| --- | --- |
| 机会与到访 | 一次购买去重为一个机会。每次现场接待按一次家庭行程计组次，参与成员计人次，看过的房号计逐套反馈。多项目路线到各项目的到站可各记一次，总部组次按行程去重。复看按同机会同项目第二次及以后独立实到判定。线上、自然到访另列。 |
| 接受与赴约 | 接受率为期间有效发出邀约中已接受的邀约数除以有效发出数，显示统计截止时间。赴约率按最终约定日统计已到期的有效已接受预约链，已履约为分子。到期前双方取消单列，逾期未到入分母。未到期、改约旧节点、自然到访不入分母。**仅约定时间前发起的改约延续当前预约链；超过约定时间未履约（爽约）后原链锁定完结，后续再约须建新链，禁止覆盖原逾期记录。** |
| 项目与销控 | 在售项目数按授权范围内有在售批次的项目去重。时点库存按房号当时状态分组，可售货值为有有效价的可售房总价之和，缺价单列。累计签约去化率为该批次当前有效签约房号数 / 累计正式推出的唯一房号数，展示分子分母（项目正式撤出销售或转自持的房号按有凭证的批次变更调整分母并留痕）。 |
| 经营与预测 | 净签约套数为期间生效签约减期间撤销，金额同口径。目标、预计签约和实际签约单列。代理项目直接贡献按归属服务收入扣对应外部服务费、内部提成、直接费用，自销按财务确认的收入口径及项目成本。签约额、应收未收、实收和净贡献分别展示。跨店合作总部仅计一单，两店另列贡献份额。 |
| 房源经营分析 | 记录授权范围内实际展示、入选、带看、有反馈放弃及改选同盘其他房的家庭数，按房号与机会去重。并列展示明确原因、未知数、价格/房态变化和观察期。经理可据此派发补资料、实地核验等任务。 |

## 6. AI 功能契约

**FR-15　口述复盘与跟进草稿。** 销售自行口述或使用已获授权的沟通材料。**若配置了受控转写服务（ASR），先由其提供文本再送天枢 AI 网关提取；当仓库/环境尚未接入服务端 ASR 时，支持复用端侧/输入法语音转文本或直接文本输入降级，不得阻断流程。** 页面逐项展示原话片段、说话人/待确认、房号、成员偏好、共同结论、下一动作、原始时间表述和可选归一化时间。销售可修改、删除或单独采纳。相对日期参照发生日和当地时区。“下周再说”只能生成待确认事项。草稿经用户确认后在一次业务提交中写跟进、获准偏好和待办，再次点确认返回原结果。人工修改保留校订记录。不同意使用语音、识别失败或模型停用时可继续手录。

**FR-16　匹配、提醒与经营辅助。** 先由服务端按权限、有效房态、预算等硬条件筛选，再由 AI 根据获准资料说明每套的匹配点、家庭分歧及待核问题。**AI 结构化输出须经过 Schema 校验与服务端硬规则二次拦截（过滤越权字段、停售/过期房源与超预算项），防止模型幻觉写入。** 每项可核验的事实带房号/资料版本与时间。零匹配时展示卡住的条件，客户同意放宽后方可另列替代方案。AI 可建议今天先处理哪个客户承诺、草拟邀约、把已分享反馈转成复看议程、从新价表提取差异供负责人审核、按授权样本做经理复盘。事实不明显示待核实。经理看到的统计必须和正式报表一致，并显示样本数与未知数。

**权限、质量和费用。** 检索、模型输入、工具动作和输出均带当前租户/岗位及业务范围校验。模型只输出候选与草稿。客户触达、资料正式发布、房态、价格、权益裁决、佣金均由获授权的人和确定性规则处理。AI 运行记录模型和提示版本、证据、调用成本、人工采纳/修正与错误原因，沿用平台计量及租户限额。原始语音及敏感片段按租户的授权和保留策略管理。用含方言、错名、成员意见相反、相对日期、无可售房和私密客户的样本统计字段准确率、人工改正率、平均归档耗时。质量底线为越权披露、违反硬条件推荐、未确认写库和重复写入均为零。

## 7. 开通、迁移与集团运营

**FR-17　租户开通和存量迁入。** 复用天枢登录、应用目录、租户许可、用户、角色、组织和菜单。房产业务模块以 CRM 为基础能力，开通向导检查两项许可及岗位授权，提示有权管理员处理缺项。停用行业写入口后保留历史账据。旧 CRM 对已纳入房产业务的数据仍执行原有隐私限制。单店有默认角色、一家门店、一个公海、手工派单和简单审批。保护期、领取上限、库存新鲜度、提醒和分佣规则按租户或项目配置。首次试用可采用标明来源的测试策略。正式营业前由指定负责人确认规则。

迁移涵盖历史客户/机会及负责人、房源及价表、未完预约、未结佣和期初余额。导入先预览行号、匹配依据、错误字段、跨库关联和总金额。同一批次重试可续办，重复行按外部编号或已确认映射去重。核对成功/失败数和金额后才能确认正式结果。旧 CRM 单人客户、无家庭、无房产扩展的跟进照常读取。提供错配纠正和批次对账，已发生后续交易的导入更正走有历史的调整。

**FR-18　集团组织与运维。** 同一租户可有集团、城市、门店、项目/案场、团队、多法人和兼职员工。总部政策按组织与生效日期继承，可在授权范围内配置区域/项目例外。业务发生日的有效规则写入单据。同优先级冲突时要求处理人选定有效版本才发布。跨法人款项分主体、币种核对，薪资/财务适配器要有字段映射、外部回执号、失败重送与期间对账。同一人不同岗位可切换工作身份。集团汇总只包含授权组织，租户间访问始终隔离。

常用列表后端分页并限制单页数量，导出用异步任务，下载时重新鉴权。集团验收数据量为单租户一万员工、一百万客户、一千万跟进，模拟一千活跃并发混合读取日程、写跟进、抢热门房号及月结。**数据库与查询工程基线**：高频列表（客户/机会/跟进/日程/房源）强制按 `(tenant_id, owner_user_id, ...)` 与 `(tenant_id, created_at)` 建立复合索引并采用有限深度/游标分页，禁止对私密字段或千万级大表执行无索引前模糊 `LIKE` 扫表；导出与重计算任务独立队列并支持租户级限流降级；移动端断网草稿本地加密存储，用户离职或撤权时由服务端下发失效信号并在端侧请求鉴权失败时清理敏感缓存。常用查询 P95 初始目标 ≤2 秒。实时房态试点目标为前台在线、普通负载下，从本系统确认变更到其他端可见 P95 ≤5 秒。外部案场未确认的等待时间单独显示。按机型记录 App 日历和 3D 真机结果。记录测试数据、持续时间、失败率、延迟、队列积压及恢复核对结果。这些数值是验收目标。**备份与恢复目标**：交易、房态和财务数据恢复点目标（RPO）≤5 分钟，恢复时间目标（RTO）≤2 小时，每季度至少演练一次并核对未完事项、占用、事件和余额。集中开盘按 FR-20 单独压测，目标为单项目 500 人同时选房时选房确认 P95 ≤2 秒且同一房号只成交一次。

**FR-19　统一通知中心、防重与消息脱敏。** 派单签收、改约、代班、停售/变价影响、锁房将到期、付款逾期、审批结果与工单升级统一进入通知路由。按 `(tenant_id, event_type, target_user_id, opportunity_id, biz_version)` 做幂等与聚合去重（同一业务变动命中同一机会多个入口仅发一次合并通知）。通知标题和摘要严格执行机会隐私裁剪与客户勿扰时段检查，严禁在站内信或推送弹窗泄露私密客户姓名、电话或原话。推送失败或用户关闭推送时，事项仍保留在站内通知和今日工作中；关键事项（锁房将到期、签约期限、代班指派）在指定时间前未读的，升级通知其经理。员工可按类别设置接收方式，但关键事项不可关闭。

**FR-20　认筹排号与集中开盘选房。** 开盘前客户可登记认筹（诚意金或无金额登记），记录认筹编号、意向户型和批次、诚意金收退。认筹本身不占库存。项目可按认筹顺序或摇号确定选房顺序；摇号需记录参与名单快照、方式、结果和监督人，结果发布后不可修改。开盘当天按顺序叫号，客户选定房号后由案场在限定时间内确认锁定并转认购，未在时限内确认的自动跳过下一位。集中开盘期间房态更新与选房确认须满足 FR-18 的并发目标，大屏或现场看板只显示房态，不显示客户信息。未选到房的认筹按规则退诚意金或转下一批。

**FR-21　个人信息与销售合规。** 采集客户联系方式、家庭成员和语音前记录告知与同意（同意范围、时间、方式、版本）。仅有称谓的家庭成员不另需同意；登记其联系方式时按其本人同意处理。客户可申请查阅、更正、删除或撤回同意：删除申请经审核后对个人资料脱敏或删除，已成交的合同、财务和审计凭据按法定期限保留并只留交易所需字段。各类数据的保留期限由租户配置，到期自动脱敏。对外发送的选房页、推荐话术和 AI 草稿不出现“必涨”“保值”“学区保证”等承诺性表述；项目资料中的学区、配套、交通如无凭据显示“待核”。外呼和短信遵守勿扰设置与租户配置的时段。

## 8. 面向开发的工程契约

### 8.1 在现有仓库落地

项目根目录为 `saas_basics/`。以当前检出分支为准核对下列入口。后端沿用 Spring Boot、MyBatis-Plus、MySQL 和 Flyway（当前分支迁移已至 `V93`，新增迁移须选未占用的 `V94+` 版本，行业扩展表遵循 `biz_` 前缀约定）。基础 CRUD 复用实体及 Mapper，复杂查询和聚合放在所属模块的 Mapper XML。PC 沿用 Vue 3 工作台，App 沿用 uni-app。新增房产行业模块，接入主应用依赖、权限、`@RequireTenantFeature` 租户开关及已有可靠事件表 `plat_outbox_event`（`PlatformOutboxService`）。通用 CRM 主档和资金原始凭据共享 ID。可为房产新增行业表、分页查询和业务动作。

**开工前必改的仓库既有基线约束（实查确认）：**
1. **旧 CRM 越权、无分页与公海泄漏**：`CrmController` / `CrmService` 当前列表接口均无分页；`listCustomers(isPool=1)` 经 `PoolBypassMarker` 豁免后直接暴露电话且无脱敏；`createReceivable` 未校验关联合同的 `tenantId` 归属，`approveReceivable` 缺少 `@Transactional` 与状态机幂等校验；`returnCustomerToPool` 直接将客户主档 `isPool=1` 并清空 `ownerUserId`。开工须优先封堵越权/漏租户校验、拦截多机会客户的旧入口直接退海，并在行业检索层屏蔽“仅摘要”私密客户的姓名/电话 `LIKE` 命中。
2. **跨店协作与 `@DataScope` 冲突**：`CrmCustomerMapper`、`CrmBusinessMapper` 等均挂载了单部门单负责人 `@DataScope(unitColumn="dept_id", userColumn="owner_user_id")`。跨店协作或一客多机会共享主档时，行业层不得依赖旧 `@DataScope` 直接读取，须在行业授权表校验后显式按机会/协作范围受控查询。
3. **AI 语音与移动端测试现状**：`AiGatewayFacade` 目前仅提供文本 `complete(ChatCompletionCommand)` 接口，无内置 ASR 转写服务；`mobile/package.json` 现有 `npm test` 仅覆盖加解密与基础状态脚本，尚无独立 lint/typecheck 脚本，行业模块须补充对应接口单测与真机验证。

### 8.3 接口与事件样例

下列路径均为**拟新增的业务接口**。统一以 `/api/real-estate` 为示例前缀。已有 `/api/crm` 保持原契约及平台响应包装。行业端从上下文取租户/操作者，普通客户端不得指定收款确认人或绕开审批。查询返回数据版本、可执行动作与裁剪后的字段。列表默认 20 条，最大 100 条。分页结构沿用仓库规范。

| 接口组 | 最少查询与写动作 | 响应或冲突处理 |
| --- | --- | --- |
| 客户、机会与公海 | 查询我的/团队摘要/池列表和时间线。创建机会并关联 CRM 客户，增删成员/偏好，设置可见性，派单/签收/拒收/投海/认领 | 返回机会 ID、授权字段和当前责任人。重复线索返回脱敏候选。并发认领失败提示状态已变更。 |
| 工作计划与带看 | `GET /work-plans?date=…`、创建邀约/接受、`POST /visits/{id}/reschedule`、签到、提交复盘、转交与完成任务 | 改约返回新预约 ID、链 ID、版本。时段冲突返回可见的冲突资源及可选时段，不能携带另一客户身份。 |
| 项目与库存 | 查询项目/分期/房号/模型绑定。提交价表预览 → 发布。`POST /units/{id}/hold-requests`、确认/驳回/释放、按版本拉取库存 | 返回项目资料版本、库存更新时间、申请状态与有效锁状态。旧版本申请返回可见最新版本供刷新。 |
| 交易、OA 与财务 | 发起优惠、回写审批、认购、维护买受人材料与分期应收计划、`POST /orders/{id}/confirm-signing`、二阶段换房/退订、认领到账、计提/复核/发放/冻结/冲回、提交异议 | 原单、凭据、规则版本、付款计划及受益明细可查。换房审批失败自动释放新房。回调重复返回原回执。过期报价或未解除库存冲突拒绝签约。 |
| AI、后续服务与集团 | 建/改/确认草稿、匹配房源、创建/撤销分享（含轻认证校验）、提交反馈、接/转/重开工单、通知中心/标记已读、审计检索、运行指标查询/导出、试导/查错/正式导入 | AI 返回来源、Schema 校验结果及待核字段。通知按业务版本去重且不泄密。外部回执没到显示待处理。后台任务返回批次 ID 和可重查结果。 |

写动作使用幂等键。再次发送相同参数返回原结果。同键不同参数报冲突。幂等记录归属于租户、调用者/业务来源和操作。更新带 `expectedVersion`，并发依靠数据库事务、条件更新或唯一占用，服务端检查影响行数。客户端区分字段校验、无权、资源不存在/不可见、版本冲突、占用冲突、凭证过期和依赖不可用。无权查看的对象使用一致的不可见响应。业务拒绝不会返回成功。审批回写、库存同步、佣金计算、提醒发送各自保存去重键、重试次数和最终回执。

例如代理销售为 3 栋 803 室（内部房源 ID 50803）提交申请。路径参数一律使用内部房源 ID，不使用可能重复的展示房号。HTTP 请求带登录态和 `Idempotency-Key: hold-demo-001`，服务端检查房源归属、销售授权及版本。

```http
POST /api/real-estate/units/50803/hold-requests
Content-Type: application/json
Idempotency-Key: hold-demo-001

{"opportunityId":3001,"quoteVersionId":91,"expectedVersion":7,"requestedUntil":"2026-12-05T18:00:00+08:00"}
```

```json
{"success":true,"code":"OK","message":"success","data":{"requestId":8401,"requestStatus":"PENDING_CONFIRMATION","unitId":50803,"unitLabel":"3栋803","unitStatus":"AVAILABLE","inventoryVersion":7}}
```

这里房态仍为上次有效确认的结果，界面同时提示存在待处理申请。只有案场确认事务成功才形成 `HELD` 并增加库存版本。若另一单抢先确认，给当前申请留失败回执。示例 ID 和日期为测试值。客户端按 requestStatus 展示“已申请，待案场确认”。

## 9. 可复现的验收用例

用两个隔离租户。租户甲设两家店、一个自销项目、一个代理项目、两位销售、经理、案场、财务和客服。使用测试家庭陈女士、先生及只登记称谓的母亲，绑定三套可售房和一套停售房。租户乙建同案名、同房号的项目。实际验收记录账号角色、环境/版本、输入、实际结果和业务单号。表内是**预期结果**。

| 用例 | 操作与可核验结果 |
| --- | --- |
| U01 建档与去重 | 夫妻共用电话，选择同家庭不同人，母亲无电话。家人可分别记录通勤、电梯需求。比较三个楼盘仅一条机会。另给父母买房另计一条。未认购时误并可还原关联；若已进入认购或核佣阶段，系统阻止物理拆档并引导发起关联修正。 |
| U02 私密机会 | 销售对自拓机会设仅摘要。经理从行业页、通用 CRM、搜索建议、导出、通知、文件和 AI 查询，仅拿到授权摘要；**按该私密客户的姓名或完整手机号搜索时返回空结果，无法反推身份**。再用同一家庭的公开机会查询，也读不到私有原话。公司派单机会至少展示租户配置的最少履约字段。 |
| U03 来源与抢客 | 公司派给甲、甲转乙、乙将**机会 1**投海；同一客户在丙手上的**机会 2**不受影响，旧 CRM 客户级退海返回歧义拦截。丙丁并发认领机会 1 仅成功一次。原始来源仍为公司，能追到甲乙。原顾问看本人贡献。另一笔自拓机会走同流程仍保留自拓来源。 |
| U04 邀约与改约 | 接受周六预约，重试提交，周六到点前改约周日：PC/App 只有一个有效预约链，周六历史和原因可查，旧提醒失效。**另测周六到点未履约（爽约）后再约周三：原链锁定为逾期未到不抹除，新约生成独立预约链。** 婉拒保留原因及下次联系安排。 |
| U05 日带看与代班 | 顾问请假，经理指定同事 B 代班（若 B 该时段已约则提示冲突），**预约结束时刻立即收回客户电话查阅权，但在 24 小时宽限期内允许 B 提交/修正本次接待单复盘且不暴露客户历史全量资料**。两位家人同场看三套，报表为一组、两人次、三套反馈。另测未到、自然到访、线上完成及独占时段冲突。 |
| U06 项目档案 | 一期已交毛坯、二期在建精装。点二期具体房号能查合同交付约定、精装清单和项目联系人。产权资料缺失显示待核，外部选房页看不到内部对接电话。 |
| U07 房态实时与 3D | 两个账号打开同一项目。PC 锁房后 App、房表、可售数和推荐同步变化，断开重连后结果一致。3D 可旋转并点到已绑定楼栋，未核楼栋不会打开另一栋。另测无库存和零库存。 |
| U08 代理与并发 | 代理提交锁房申请，刷新和重试仍显示待回执。案场确认才显示有效锁。两笔申请或两个自销账号争同一房，至多一条有效锁。旧取消回执不能解新锁。**若已认购房源收到外部台账冲突或过期回执，原认购单保持不覆盖但立即阻断签约并生成高优核查单。** |
| U09 停售、报价与换退 | 已约房停售产生一条负责人任务，旧价报价过期无法签约。优惠审批重复回写只生效一次。**换房申请期间原房保持锁定；新房占房失败保留旧单；若新房锁定成功但换房审批驳回，系统自动释放新房并维持原单有效；审批通过后原子释放原房。** 退订获批后分别核对退款和库存恢复，并同步回退对应 CRM 商机阶段。 |
| U10 佣金核算 | 执行第 5 节标准样单。两次到账、两人贡献、一次跨期退费，逐笔金额完全匹配。重复到账回执不重复计提。冻结推荐人份额不影响已批准的成交人份额。 |
| U11 售后与 OA | 签约生成交接清单和承诺。客服转开发商后仍有内部经办人，超时升级，回访未解决可重开。报销批准后能在对应项目成本查到一次。 |
| U12 AI 确认与勿扰 | 口述“母亲想靠电梯，我先生还没定，下周再说”。草稿区分提出人并留待确认时间。人工改字段、确认两次只写一次。客户明确勿扰后，AI 和计划均不发起对应联系。 |
| U13 AI 推荐与失效 | 硬预算上限 280 万，库存含 270 万可售、275 万停售、290 万可售。结果仅推荐第一套并列房号和版本。第一套变过期后结果为空。停用模型后人工查房和跟进可用。 |
| U14 家庭选房和多店协作 | 已邀请成员把 A 房意见设为仅自己，顾问与其他人均不可见。公开的问题进入复看议程。撤销分享后旧链接与资源访问失效。跨店联卖可查协作历史，总部汇总只计一套。 |
| U15 置换、候补与费用比较 | 锁房 12 日到期，旧房款预计 18 日到账，显示相差 6 天及依据。候补登记本身无有效锁。比较门店承担的 8,000 元车位补贴与 2 万元让价，经理看到相差 1.2 万元，对客页只显示批准权益。 |
| U16 指标核对 | 某日三条到期已接受预约链，一条实到、一条未到、一条到期前双方取消。另有一次自然到访。赴约率为 1/2，自然到访另外一组。项目当期签三套、撤一套，净签约为两套。零分母显示无样本。 |
| U17 迁移、隔离与恢复 | 导入四类存量资料，含重复客户和无效房号。异常标行，修正重试后总数、期初余额可核对。租户乙无法查看甲的数据、文件或缓存。恢复后核对未完事项、占用、事件和资金余额。 |
| U18 集团与真机 | 按第 7 节规模混合压测并报告指标。跨岗、跨法人重送、关账和批量导出可对账。移动真机断网保存草稿，恢复后重试仅生成一条记录。离线不能确认锁房、签约或发佣。 |
| U19 提醒、资料变更与经理复盘 | 改价草稿须负责人确认后才影响房表。变价命中同一机会的两个入口只生成一次同类提醒。经理查看“带看多、改选多”的房号，可见样本数、未知原因与统计期间，可派补资料任务。 |
| U20 集团开通与政策 | 试点店可见已开通的双端菜单，停用后直接请求行业 API 也被拦截。总部新政策于次月生效，门店已批准的例外与历史结算各有可查依据。跨法人凭证重送只入账一次。 |
| U21 合规材料、付款计划与通知防重 | 认购后填写买受人证件与按揭预审缺项，生成定金/首付/放款分期计划并向个人计划推送临期催办。非授权销售及经理不可下载证件附件。变价命中同一机会两个入口时仅生成一条合并通知；勿扰时段与私密客户通知不泄露姓名和电话。家庭选房页未经尾号核验不可打开。 |
| U22 审计、离线撤权与阶梯退佣 | 查看私密电话、手工改房态、改价、客户拆并及导出均产生不可篡改审计记录。员工在移动端保存离线草稿后被撤权离职，端侧重连鉴权失败时本地敏感缓存被清理且无法补传。另外按月累计 3 套触发阶梯跳档后再退 1 套且前两套已发佣，系统按项目口径重算并生成个人待抵扣负向欠款台账而不篡改历史已发凭证。 |
| U23 交易环节披露与撞单 | 私密机会发起特价审批，审批人可见房号、报价版本和理由，看不到私密原话。两位销售先后报备同一号段，第二笔进入待裁决；裁决后败方份额冻结、胜方生效，记录依据。客户在他人保护期内自然到访，登记后原报备人收到通知且归属不变。迟到 20 分钟记实到并标迟到；超过宽限记爽约，经理凭沟通记录改判为到点前改约后，原链延续且修正留痕。 |
| U24 认筹开盘与认购违约 | 30 组认筹按摇号确定顺序，结果发布后不可修改。两组同时选同一房号仅一组成功；超时未确认自动跳号。另测认购超期未签：到期生成违约处理单，定金处置审批生效前房源保持认购态。按揭被拒后转一次性付款，付款计划重算。代理项目登记开发商回执的首付进度，本公司收款余额不变。 |
| U25 个人信息与合规 | 客户撤回同意并申请删除：未成交机会的资料脱敏，已签约机会保留合同和财务所需字段并记录处理依据。备案价 300 万、允许下浮 3%，审批 290 万报价时系统阻止提交。AI 推荐草稿含“必涨”时被拦截。车位单独成交与住宅组合成交分别计价、计佣。 |

上线前以一笔完整业务串起各岗位。操作顺序为家庭建档 → 公司派单或同事交接 → 邀约改期 → 代班实到 → 逐套反馈 → 换备选 → 批价签约 → 两次到账与拆佣 → 售后交接。另走一笔退订/跨期调整。每个角色用自己的账号实际操作。库存、报价、金额、权限出现差错时修正并重跑原用例。
