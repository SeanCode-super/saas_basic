# 天枢房地产销售平台开发实施方案

开发排期基线 · 2026 年 11 月 28 日。适用于新房自销、代理案场与销售门店。排工表按本方案第 7 节的工作包编号分派。业务字段和案例可对照[产品方案](房地产销售与团队经营平台产品方案.md)。

## 1. 交付目标和范围

先交付一家门店可用的天枢原生应用。销售在 App 上从已有客户建档、安排每天工作和带看，到跟进交易、查看提成。经理在 PC 和 App 分客、排班、代班和审批。案场维护房源并确认到访、房态与交易。财务按实际到账核对公司应收与个人提成。客户签约后，承诺、交付和客诉有明确经办人。后续让城市公司跨店经营，再验证集团规模。

| 纳入开发 | 明确边界 |
| --- | --- |
| 原方案的销售工作台、案场与交易、团队与 OA、财务经营、成交后服务、AI、租户上线和集团推广 | 删除原第一项「获客与渠道运营」。广告投放、营销活动、公开留资/拉新页、获客成本与投产分析、外部渠道自助门户均不排期 |
| 手工建客、公司资源导入、原始来源、同事转交、公海、老客户引荐关系、贡献归属 | 公司现有 CRM 可继续交付存量客户。仅记一次业务的来源与引荐关系。已有客户的家庭选房页采用定向分享 |
| 合作项目、内部案场报备、开发商回执、合作单位应收应付和内部提成 | 录入与查验由获授权的内部岗位完成。可登记已有合同的外部费用与回款 |
| 在售项目资料、房源台账、销售统计和现有 3D 沙盘入口 | 时间日照、楼栋精细户型、样板间单列为后续储备。本轮只确认资料要求与验收方法 |

**交付基础。** 仓库已有通用 CRM 客户/公海、跟进、商机、合同与回款，以及组织、权限、工作流、AI 和双端工作台。玉带湾已有本地 WebGL 沙盘及三维资产。这些是复用入口。房产应用开通、日计划、真实库存同步、结算、设备验收和集团容量均需本次项目实际交付。

## 2. 人员、排期与上线节点

估算按 8 个全职席位：产品/交付 1 人，后端 3 人（含技术负责人），PC 前端 1 人，App 前端 1 人，AI/集成 1 人，测试 1 人。界面设计、运维和财务/案场业务代表在相应节点参与。第 1 周从人员和试点样本到位起算，每周 5 个工作日。排工表人日为全组实现、联调与验证的合计估算。排班窗口另留评审、缺陷修复和试用反馈时间。下表是派工基线，产品负责人在第 2 周末按实际人手、样本和设备重估。

| 阶段 | 窗口 | 阶段交付与验收人 |
| --- | --- | --- |
| A 启动与基础 | 第 1–2 周 | 产品负责人带销售、案场和财务签认业务样单。技术负责人演示租户开通、角色可见范围和双端入口 |
| B 日常销售 | 第 3–6 周 | 一线销售在 App 完成家庭建档、邀约、日带看、工作计划和复盘。经理用 PC 处理分派和代班 |
| C 项目与交易 | 第 7–10 周 | 案场人员维护价表、房态和报备，两个真实账号联测停售改约、认购、优惠审批和签约。销售能在项目详情切到 3D |
| D 门店试点 | 第 11–14 周 | 财务用历史订单复算提成，业务人员完成结佣、售后交接、AI 辅助、存量导入与异常演练。试点负责人签验收记录 |
| E 城市多店 | 第 15–20 周 | 城市负责人验证跨店协作、进阶销售工具、完整 OA 与售后、经营报表和跨期调整 |
| F 集团交付 | 第 21–26 周 | 总部验证分级经营、多法人、财务薪资接口、隔离与容量。运维和业务共同完成灰度、恢复与扩大租户范围决策 |
| R 后续储备 | 待专项排期 | 日照、户型、样板间各有资料清单和业务验收人，单独估工，不计入 26 周 |

按工作包汇总，A 至 D 共 22 包、373 人日，完成门店试点。E 阶段 8 包、154 人日，F 阶段 5 包、104 人日。已排 35 包合计 631 人日。另有 3 个储备包待估。使用[开发排工表](../outputs/01a21d9d-3379-7a80-b8ca-533bca2994b4/房地产销售平台开发排工表.xlsx)可按负责人、阶段、计划周和状态筛选。

第 1 周并行开 A01、A02、A03。业务方提供脱敏客户与家庭样本、一份带分期和房号的真实价表、一份案场变更通知、排班表、已结佣样单以及退款或补发示例。缺少某种样单先用标注的测试数据开发，正式试点前用真实脱敏样单复核。QA 自第 1 周建验收账，演示可复现操作和预期金额。

| --- | --- | --- |

## 4. 日带看与工作计划的开发规格

**两个入口共用同一份业务记录。** 「日带看」只列看房行程，按接待时间排列。每项显示购房家庭、实际参与人、项目、集合点/导航、房号清单、主销售/案场接待、已确认事项和状态。「工作计划」汇集回电、邀约、带看、发资料、核价、经理指派、售后回访，支持销售自己建任务、设优先级、起止时间、提醒和目标。可指定到日而不定时，也可设置周目标、拆成日任务。双端支持改期、委派、完成、查看历史。

| 环节 | 业务规则 | 验收实例 |
| --- | --- | --- |
| 预约 | 客户接受邀约后，关联生成一次带看和一条日程。一个家庭在同一次行程看多套房可登记多条房源。多项目分站记录案场和次序。同一销售、接待或受控场地撞档时显示冲突和可调整时间 | 手机重试提交两次，PC 日历只出现一个预约。已预约的案场时段不能被第二人重复占用 |
| 改约与替班 | 保留原时间、原因与改约链，旧提醒作废。销售请假时列出待处理事项，经理指定代班，仅共享必要资料。客户主动取消或未到，记录原因和下次联系人 | 周六改到周日，周六依然能查改约历史，实际到访只在真正到场的日期计一次 |
| 实际带看 | 支持现场签到、自然到访补录、线上看房另列。保存实际起止、实际参与人、逐套反馈、现场核验事项、附件与回访承诺。待确认的 AI 草稿可编辑 | 二位家人看三套房，一组到访、两人次、三套反馈。未到不计实际带看。补录保留操作人与录入日期 |
| 每日复盘 | 日计划列计划、完成、改期、逾期和待办。下班前可转次日或安排接手，每项有原因。经理可按团队、员工、项目、日期看计划和实际，不公开受保护的客户身份 | 今日一项未完成承诺转明日，原记录可以追溯，负责人只收到一次新提醒 |

**指标统一。** 用业务所在地时区和业务发生时间归日，保存原时区。今日计划带看按当前有效、计划在当天的行程计，另存排班快照用于复盘原计划。实际到访组次按现场到访事件计，自然到访单列。邀约赴约率取观察期内已到期的已接受预约链，按最终有效预约的约定日归属，分子为其中已履约链。到期前双方约定取消的单列，到期未到计入分母。尚未到期、自然到访和重复改约节点不计入。分母为零显示“无样本”。

## 5. 工程实施与关键契约

**接入已有平台。** 建议在天枢后端新建房产行业模块，按租户开通，PC 使用现有 Vue 工作台，App 进入现有 uni-app 工作台。沿用平台的行业应用目录、菜单、租户、成员和 API 权限。先核实并登记接口再挂原生页面。日历、销控和 WebGL 采用专用组件。简单增删改查用 MyBatis-Plus，分页聚合、跨实体经营查询放在所属模块的 Mapper XML，按平台约定做 Flyway 增量迁移。以下是拟建模型与接口，不代表现成接口。

| 数据归属 | 关键记录与约束 |
| --- | --- |
| CRM 主档 | 复用 CRM 客户、商机、跟进、合同和回款 ID。家庭成员可仅有称谓。获联系方式后再关联客户。购房机会映射商机，候选楼盘关联项目。来源有原始证据，分派/转移/贡献为各自的有序历史 |
| 行业项目与房源 | 项目、地块、分期、批次、楼栋、单元、房号、授权范围、联系人、交付与产权资料、价格版本、房态事件。房号业务键含租户及上级范围。暂停售、待确认、锁定等状态有不同的可推荐/可交易条件 |
| 日程与团队 | 邀约、预约链、带看及逐套反馈、任务、指派、提醒回执、资源占用。唯一业务事件关联日程。接收人、时间和版本共同识别有效提醒。可按租户/负责人/日期、项目/时段分页查询 |
| 交易与资金 | 报备凭证、成交单、报价版本、锁定记录、审批单、贡献快照、提成规则版本、可结算明细、发放批次和调整单。保存法人、币种、业务时间和操作时间，金额用定点数。复用已核实的回款单，外部购房进度和本公司的应收款分单据记录 |
| 服务、权限与审计 | 交付承诺、服务工单、回访、临时授权、分享凭证、变更/通知事件和业务回执。历史单据保留发生时的组织快照。当前访问按当下任职和授权校验 |

**接口先行。** 房产业务路由建议统一到行业模块内，如 `/api/real-estate`，以 A02 契约评审为准。客户/家庭、项目/库存、日程、交易/财务、售后工单分别对外提供分页查询和显式业务动作。例如 `GET /work-plans?date=&ownerId=`、`POST /visits/{id}/reschedule`、`POST /units/{id}/hold-requests`、`POST /orders/{id}/confirm-signing`。每个契约交付字段、可见性、状态枚举、成功示例、冲突/权限/过期结果和可重试条件。租户和操作者取登录上下文。财务/锁房/审批回写带业务幂等键，修改带记录版本。旧客户端与旧 CRM 编号继续受支持。

**权限与事务。** 服务端执行租户、组织/项目、机会共享范围、字段四层授权，通用 CRM、搜索、导出、附件、通知和 AI 走同样规则。优先改造现有公海直接读取电话、列表全量读取和先读后写认领路径。用事务中的条件更新或唯一占用保证同一机会只认领一次、同一房号最多一个有效锁。业务提交与待发布事件同事务，后台可靠重试并记录消费回执。PC/App 先取快照和版本，再订阅变更，重连按版本补齐或重新取快照。审批通过且原单仍可变更时才回写。重复回执安全忽略，版本冲突进入人工核查队列。

| 试点规则 | 默认行为及可配置项 |
| --- | --- |
| 销售与上级 | 销售逐机会选择“向直属经理公开”或“仅共享摘要”。摘要含匿名机会号、阶段、是否逾期和求助事项。姓名、电话、家庭原话、语音及个人备注单独授权。公司派客所需履约资料在接单前明示。跨店经理和总部默认只看授权汇总 |
| 公海与代班 | 待认领只显示脱敏摘要。认领后跟进本次机会，原负责人保留推荐回执与本人贡献凭据。门店可配置公海范围、在手上限和保护期。代班授权绑定预约和时间，到期撤销 |
| 案场与财务 | 案场可确认本项目报备、实际到访及获授权的房态。财务只取合同、结算主体、回款凭据和已确认贡献。经理可申请调整归属，财务核准资金单据，历史变更注明理由 |
| 指标与经营 | 个人意向分和实际交易阶段分别保存。团队报表可查有效沟通、实际到访、复看、成交、净签约和实收。项目直接贡献须注明期间与口径，代理业务以归属服务收入扣对应外部费用、内部提成与直接费用，自销业务按财务确认的收入与项目成本口径计算。经营应收、实收现金单列，避免跨期混算 |

**状态与资金。** 购房机会只有一名主责人，交接待签收期间原主责继续履约。锁房区分“请求受理”和“有权方已确认”。自营可售 → 有效锁定 → 认购 → 签约。申请失败、超时释放、换房、退订使用独立事件。变更批准、退款到账、恢复可售按实际条件分别处理。提成依次为预计、满足计提、已复核、可发、已发。冻结、冲回和补发引用原明细。分摊尾差按规则落到指定角色，全部份额与本期可分配额相等。历史发放单只做引用原单的差额调整。

**AI 交付。** 企业授权的语音经转写和字段提取形成草稿，保存证据片段、校订值、操作人与模型版本。用结构化条件过滤预算、真实可售、近期确认和权限，再生成推荐说明。模型无权自行发消息、批准价格或确认房态/佣金。资料不足返回待确认。试点准备含方言、人名近音、相对日期、家庭分歧、过期资料和勿扰标志的脱敏样例，分别统计成员/日期/房号提取准确率、人工修改率、归档耗时与推荐转带看。硬约束越界、泄露私有字段或重复写日程为上线阻断缺陷。模型不可用时人工流程照常。

**仓库落点。** 技术负责人先核对[CRM 控制器](../server/saas-basics-module-integration/src/main/java/com/saasbasics/platform/modules/crm/controller/CrmController.java)、[公海及客户服务](../server/saas-basics-module-integration/src/main/java/com/saasbasics/platform/modules/crm/service/CrmService.java)、[PC CRM](../web/src/views/crm/CrmView.vue)、[移动 CRM](../mobile/src/pages/crm/customers.vue)、[行业应用接入](DEVELOPING_INDUSTRY_APPS.md)、[工作流模块](../server/saas-basics-module-workflow)和[现有沙盘](../work/visualizations/yudaiwan/index.html)。双端新旧入口以及行业开通前后都纳入回归。

## 6. 试点、切换与交付证据

1. **迁入旧业务。** 按客户、房源、未完预约、未结佣四种模板做预检和重复识别，输出行号、匹配依据及修正意见。首轮试导核对总数、未分配项、预约责任人和分户未结余额。校验通过后按批次正式导入，重复上传同一批不重复建账。兼容旧客户无家庭档案、旧跟进无房产扩展字段。
2. **用同一单跑全岗位。** 夫妻先后建档，经理派单后换顾问，旧销售保留贡献。客户接受周六带看后改到周日，原销售请假完成代班。中途停售一套，案场确认备选。App 口述生成逐套反馈，经销售确认后写入回访。经理批价，案场认购并签约。财务分两次核到账，售后人员接走合同资料与历史承诺。
3. **对账有标准答案。** 用产品方案中的示例，成交价 250 万元、公司应收代理费 5 万元，按实收的 20% 提取员工份额，推荐/成交按 30%/70% 分。首到账 3 万元产生 1,800 与 4,200 元，尾款 2 万元产生 1,200 与 2,800 元。再测试重复回执、部分冻结及跨期撤销。实际试点采用客户自己的有效制度，由财务确认期初、应得、已发及差额。
4. **验证错误与恢复。** 两个真实角色抢同一客户或同一房号，只成功一次。验证隐藏客户用普通 CRM、App、导出、通知与 AI 均取不到受限字段。断网草稿补传一次。审批回写重试一次生效。验证租户 A 的权限、文件、查询和缓存均不能访问租户 B。经历停机恢复后核对业务单、待办及资金账。数据泄露、重复占用/发佣、签约价错误和账实不符须在放量前修复。
5. **发布与回退。** 先增量迁移、发布兼容服务，再启用试点租户功能开关和双端入口。保留旧入口只读/可用策略与旧客户端兼容说明。应用回退可关闭行业写入、保留历史数据。已经发生的交易按账单纠正，迁移异常使用备份并对账。观察队列积压、库存延迟、提醒失败、审批回写、AI 错误率及费用。每阶段提交版本、测试环境、账号角色、操作记录、账款对比及未决问题。
6. **集团验收。** 基线按单租户 1 万名员工、100 万客户、1,000 万跟进、1,000 活跃并发组合日程读取、跟进入库、热门房号争抢和月结。常用查询 P95 初始目标不超过 2 秒，分批导出可恢复，重复有效认领、重复锁房和重复计提为零。用真实请求分布复核目标，记录峰值持续时间、失败率、资源利用、恢复时间和集团汇总差异。
