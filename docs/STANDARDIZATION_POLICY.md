# SaaS Basics 标准化策略

状态：`Accepted`

## 1. 适用范围

本策略约束后端、前端、数据库、公开 API、事件、开发工具、AI、文档、示例和种子数据。任何模块只有同时满足执行蓝图、对应能力剖面和本策略才可以标记为完成。

标准化不等于把所有概念做成万能配置，也不等于一次交付全部功能。项目允许按里程碑演进，但不发布 mock、占位 API、演示数据依赖或不能完成真实生命周期的半成品能力。

## 2. 核心原则

1. 标准优先：存在成熟公开标准时直接采用并记录版本。
2. 语义内核：没有统一标准时定义最小稳定语义内核，但能力实现必须完整。
3. 类型化扩展：地域、行业和供应商差异通过有 Schema、有版本的扩展或适配器实现。
4. 公开契约：跨模块只依赖版本化 API、事件和 SPI。
5. 默认安全：租户隔离、最小权限、加密、审计和失败关闭是默认行为。
6. 无隐式默认：地域、语言、货币、时区、凭证、供应商和行业类型必须显式配置或从标准上下文协商。
7. 可迁移：公开标识、数据格式、扩展版本和升级路径必须稳定。

## 3. 标准矩阵

| 领域 | 采用标准或规范 | 项目要求 |
|---|---|---|
| 时间 | ISO 8601、RFC 3339、IANA TZDB | 存储与事件使用 UTC；展示时区显式配置 |
| 语言 | BCP 47 | API 和配置使用语言标签，不硬编码单一回退语言 |
| 国家地区 | ISO 3166-1 | 国家扩展使用标准代码，不把行政区字段放入核心表 |
| 货币 | ISO 4217 | 金额同时包含数值、货币代码和精度规则 |
| 电话 | E.164 | 标准号码与原始输入分离，核心匹配使用标准号码 |
| 公共标识 | UUIDv7 / RFC 9562 | API 不暴露可枚举数据库主键 |
| HTTP | RFC 9110、RFC 9457 | 使用标准方法、状态码和 Problem Details 错误语义 |
| API 描述 | OpenAPI 3.1、JSON Schema 2020-12 | 公开 API 和工具 Schema 可机器验证 |
| 认证授权 | OAuth 2.1、OpenID Connect、Spring Security | 本地身份是标准 provider；保留 OIDC 和 SCIM 入口 |
| 身份供应 | SCIM 2.0 | 用户和组织交换通过映射层，不让 SCIM 模型污染领域表 |
| 事件 | CloudEvents 1.0 | 领域事件有类型、来源、主题、时间、版本和幂等标识 |
| 可观测性 | OpenTelemetry、W3C Trace Context | 日志、指标、追踪共享 trace context 并执行敏感信息治理 |
| 模块版本 | Semantic Versioning 2.0 | 公开 API、事件、SPI、模板和扩展包独立版本化 |
| AI 工具 | MCP、JSON Schema | 工具权限、风险和审批由平台治理，外部描述不能覆盖 |
| AI 可观测性 | OpenTelemetry GenAI 语义约定 | 记录模型、Token、费用、延迟、错误和安全策略结果 |
| 文件内容 | RFC 9110 media type 语义、标准校验和 | 内容类型、长度、摘要、版本和处置方式均结构化 |
| 密码 | PHC 风格算法标识、BCrypt/Argon2id | 新密码禁止无盐摘要；参数支持自动升级 |

引用标准升级必须通过 ADR，记录兼容区间和迁移策略。

## 4. 核心与扩展

核心模块只保存所有目标行业共同需要的稳定语义。扩展包必须包含：

- 唯一命名空间和语义版本。
- manifest、依赖范围、数据库迁移和兼容矩阵。
- 类型化配置 Schema，不以自由 JSON 代替主要领域模型。
- 独立权限码、错误码、审计事件和国际化资源。
- 安装前检查、升级脚本、停用语义和卸载前数据检查。
- 契约测试、租户隔离测试和公开 API 文档。

扩展包可以依赖核心公开 API，核心不能反向依赖扩展包。供应商适配器只能位于 infrastructure 层。

## 5. 完整能力剖面

一个能力标记为完成前必须具备：

- 完整创建、读取、更新、停用、恢复、归档或删除生命周期。
- 并发、幂等、重试、超时和失败恢复语义。
- 权限、数据范围、字段保护和负向租户隔离测试。
- 审计、指标、追踪、告警和敏感数据处理。
- 空库安装、上一版本升级、回滚应用版本和重复迁移验证。
- OpenAPI、错误语义、事件、SDK 或 SPI 契约与兼容性测试。
- 前端加载、空数据、无权限、失败、冲突和恢复状态。
- 运维配置、容量限制、备份恢复和故障排查文档。

单个迭代可以只实现剖面的一部分，但在全部项目验收通过前不得宣称该能力已发布。

## 6. 禁止项

核心模块禁止：

- 强制出现公司、法人、医院、学校、政府机构等行业或地域实体类型。
- 使用国家登记号、证件号、行政区、税号等地域字段作为核心表字段。
- 硬编码默认语言、国家、时区、货币、电话区号或日期格式。
- 内置生产账号、默认密码、明文密钥或可预测 token。
- 在领域层引用云厂商、模型厂商、数据库厂商或对象存储 SDK。
- 通过请求头、查询参数或请求体覆盖认证租户。
- 通过万能 JSON、EAV 或脚本绕过核心关系和约束。
- 修改已经发布的数据库迁移。
- 使用 mock 回退掩盖缺失的生产实现。
- 只做展示页面、固定统计或始终成功的占位接口并标记为完成。

## 7. 现有代码迁移

V1-V24 是不可修改的历史迁移，其中的地域默认值、演示账号和旧组织术语不再代表目标设计。后续只通过追加迁移和应用升级处理：

1. V25 创建标准 organization 核心表。
2. 标准化配置迁移移除固定时区、语言和演示联系方式，改为安装时显式配置或协议协商。
3. Spring Security 迁移删除默认密码和无盐 SHA-256 新建路径。
4. 旧 IAM 部门、岗位、员工通过显式映射迁入标准组织模型。
5. 文件、调度、集成和代码生成按完整能力剖面重做，旧展示数据不迁入生产配置。

## 8. 评审门禁

每个 PR 必须回答：

- 使用了什么公开标准及版本？
- 新概念为什么属于核心，而不是扩展？
- 是否引入地域、行业、语言或供应商假设？
- 生命周期、失败恢复、权限、审计和兼容性是否完整？
- 是否新增默认凭证、演示依赖或不可迁移数据？

无法明确回答时，PR 保持草稿状态。
